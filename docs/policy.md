# Nova 全体方針書

このドキュメントは CLAUDE.md の内容を方針書として整理したものです。
実装や判断に迷ったときは、まず CLAUDE.md（ルールの正本）を参照し、
本書はその背景・構造の理解を助けるものとして使ってください。

## 1. プロジェクトの目的

Freenove 4WD Car Kit for ESP32（FNK0053）をベースに、猫のように気ままで
愛らしい子分ロボット「Nova」を作る。

目指す体験は LOVOT のような「生命感」と「自分への反応」であり、
単なるライントレースカーや障害物回避ロボットではない。
Nova の行動は常に「反応している」ように見えることを優先し、
一方で機械的・予測可能に見えすぎないよう、気ままさ（内部状態による揺らぎ）を持たせる。

最優先は「障害物を避けながら部屋をうろうろする」こと。
反応や遊びは、この自律的な動き回りの上に積み上げる。

## 2. ハードウェア構成（M2案）

| 部位 | 内容 |
|---|---|
| 首（パンチルト） | LEDマトリクス×2面（目）と超音波センサーを搭載。servo1：左右 0〜180°、servo2：上下 90〜150° |
| 測距 | 首の超音波センサーのみ（車体前面の超音波は廃止） |
| 表現 | WS2812 ×12、パッシブブザー |
| センサー | 光センサー、ライントラッキングセンサー、IR受信、電池電圧読み取り |
| 未使用（当面） | カメラ |

**左右の定義**：文書・コード・ログの「左」「右」は、すべて **Nova 自身から見た向き**
（Nova の後ろに立ち、同じ方向を見たときの左右）とする。首・車輪・回転のどれも同じ定義に従う
（2026-09-24 定義）。

ピン番号・I2Cアドレスは独自定義せず、Freenove 公式サンプルの定義に従う。
参照：https://github.com/Freenove/Freenove_4WD_Car_Kit_for_ESP32

## 3. 振る舞いの設計原則

1. 気づく（目）→ 向く（首）→ 動く（車体）の順で反応を作る。
   いきなり車体が動くのではなく、まず「気づいた」ことを目・首の動きで示す。
2. 首の使用権は「安全＞測距＞表情」の順。走行中は首を正面・水平に固定し、
   見回しは停止中（または減速中の短時間）のみ。首が動いている間と、
   止まってから安定するまでの測距値は無効扱い。
3. 急発進・急停止をしない。動く前に小さな「ため」を入れる。
   機械的な反応ではなく、生き物らしい予備動作を挟む。
4. 反応したうえで気ままに振る舞う。
   内部状態（機嫌・興味など）によって反応の強さを変えたり、あえて反応を無視したりする。
5. 機械的な長いビープ音、派手な点滅は避ける。
   演出は控えめにし、驚かせない・うるさくしないことを優先する。

## 4. ソフトウェア構成

```
src/
  hal/         ハードウェア操作の窓口（サーボ・モーター・センサー・LED等）
  core/        状態管理・優先度による調停・全体のループ制御
  behaviors/   個々の振る舞い（1機能1ファイル）
  config.h     速度・時間・距離などの調整値の集約
```

### hal（Hardware Abstraction Layer）
ハードウェアへの直接アクセスはすべて src/hal/ を経由する。
behaviors や core から Arduino のピン操作・レジスタ操作などを直接行わない。
これにより、ハードウェア構成の変更や実測値の調整が hal 層に閉じ込められる。

### core
- ループ制御、センサー値の集約、内部状態（機嫌・興味など）の管理を担う。
- 複数の behaviors が同時に「動きたい」と要求した場合、優先度に基づいて
  1つの behavior を選び実行する（調停）。

### behaviors
- 1機能1ファイルとし、各ファイルは「自分がどんな条件で発動したいか（優先度）」と
  「発動時に何をするか」を持つ。
- 同時に複数を実行せず、core の調停によって選ばれた1つのみが実行される。

### 優先度による調停
- 各 behavior は自身の発動条件が満たされたときに優先度（数値など）を core に返す。
- core は最も優先度の高い behavior を選択し、他は待機・中断する。
- 優先度の具体的な基準（安全 > 反応 > 気まま、等）は今後 docs/decisions.md で
  個別に記録しながら積み上げていく。

## 5. コーディング規約（CLAUDE.md より抜粋）

- delay() は使わない。millis() ベースのノンブロッキング構造にする。
- ハードウェアの操作は必ず src/hal/ を経由する。
- 速度・時間・距離などの調整値は src/config.h に集約する。
- 振る舞いは src/behaviors/ に1機能1ファイル。優先度で1つを選んで実行する。
- センサー値と状態遷移をシリアル出力する（115200bps）。
- コメントは日本語。

## 6. 作業ルール（CLAUDE.md より抜粋）

- 1回の依頼では、カタログの1ID分だけを実装する。
- 依存するIDの最小版と共通部品は、同じ依頼で作ってよい。
- 着手前に docs/specs/ の該当ミニ仕様と docs/catalog.md を読む。
- 完了したら docs/catalog.md の状態を更新する。
- コミットメッセージの先頭にIDを付ける（例：「#10 見上げる：初版」）。
- IDに紐づかない変更（方針・文書・ツール）は先頭に #0 を付ける。
- 書き込み（upload）は、許可があったときだけ行う。
- 仕様の変更理由は docs/decisions.md に1行で残す。
