  **再試験で、正面衝突0回・張りつき解消を確認**（詳しくは `docs/specs/25_wander.md`「とても近いとき：後退+その場回転」）。

  あと1分以上動かなくなる現象が発生。調べたところ、実際には電圧低下（ブラウンアウト）で再起動し、
  `DEBUG_START_PAUSED`=1 のため一時停止の状態で待っていただけだった（▶ を押すとすぐ動き出した）。
- **リセット理由の記録**（common_test_stats.md「リセット理由の記録」）：`hal/hal_reset.*`（新規）で

  再びブラウンアウトを確認できた（`t`：`起動:ブラウンアウト（電圧低下）`）。**満充電でも起きる**ことを確定。
- **ブラウンアウト対策①：その場回転のキック時間を短縮**（2026-09-22、measurements.md・decisions.md）：
  `MOTOR_ROTATE_KICK_MS` を **1000ms → 300ms** に変更（`MOTOR_ROTATE_KICK_PWM` 1600・1ステップ1300ms は
  変えない）。**再試験で、キックを300msにしてもブラウンアウトが再発**（`t`：`困る:開始1/空き0`。
  後退のあとすぐ止まった）。
- **ブラウンアウト対策②：後退と回転の間に「ため」を追加**（2026-09-22、decisions.md）：
  ID15（trouble.cpp）は後退の停止から回転開始までに左右確認（実時間で数百ms、モーター出力0）が
  自然に入るが、ID25の後退+その場回転（wander.cpp）は `Motion_IsAtTarget()` が真になった

  見ておらず、車体の物理的な停止は保証しない）。新しい状態 `STATE_RECOVER_PAUSE` で
  `WANDER_RECOVER_PAUSE_MS`（500ms、仮の値）の「ため」を挟むようにした。**ビルド済み。
  書き込み・再試験はこれから**。回転角は引き続き再測定していない
  （キック時間短縮とあわせて「片側旋回の値の見直し」でまとめて確認する）。
- **共通部品**：首の調停、障害物の判定、安全層（持ち上げ＝ライン111で即停止、障害物で止めるのは前進と片側旋回だけ）、
  回転（core/motion.* にキック→保持の2段階）、首を一方向に向けて測る core/scan.*。
- **最低PWMと回転の調整値**：実測を config.h・measurements.md に反映済み。
  回転は床で調整キーを使って探した「**一旦の決定値**」（その場回転 1300ms・キック1000ms/PWM1600・保持1000で約30°、
  片側旋回 1200ms・キック300ms/PWM1400・保持1450で約20°）。TROUBLE_MAX_STEPS は 360÷30＝12。
  **注意**：その場回転のキックは、ブラウンアウト対策で2026-09-22に1000ms→300msへ変更した（PWM1600・

- **IR受信と一時停止**：hal/hal_ir.*（IRremoteESP8266、GPIO0、NEC のみ）。リモコンの ▶（0xFFA857）で一時停止／再開。

- **試験の集計と保存**（common_test_stats.md）：`hal/hal_storage.*`（NVS）・`core/test_stats.*` を実装。
  **実機確認済み**（`t` の表示、電源を切ってからの保持を確認。2026-09-22）。
  - 「再開してから一時停止するまで」を1回の試験とし、直近3回分だけ NVS にリングバッファで保存。
  - 保存は「一時停止して止まってから」「保存キー `h`」「止まっている30秒ごと」の3つだけ（走行中は書かない）。

  - `t` で表示、`h` で今すぐ保存、`x` で消去（5秒以内に2回で確定）。

## 4. 未解決の点・注意

- **`DEBUG_START_PAUSED` は 1**（config.h）。起動直後は一時停止で、▶ か `p` で開始する。
  ケーブルなしの試験ではこのまま便利。すぐ動かしたいときは 0 にする。
  試験の集計は、起動時に一時停止のままだと「再開」まで始まらない（1で始まる設定と整合させてある）。
- **書き込みは、ユーザーが指示したときだけ。書き込み前にユーザーがシリアルモニタを閉じる**（COM3 が使用中だと失敗する）。
  書き込みは `~/.platformio/penv/Scripts/pio.exe run -t upload`（fnk0053）。ビルドだけは `pio run`。ホストに g++ はない。
- **持ち上げ中（ライン111）は、`3`〜`6` も受け付けない**（安全層が止める）。床に置いて 111 が消えてから使う。
- 回転キー `3`〜`6` の1ステップの間だけ、障害物「あり」による停止を外している（デバッグ用。非常停止12cm未満と持ち上げは残す）。
  本番の ID25・ID15 は外さない。
- **書き込みで、調整キーで変えた値は元に戻る**。値を決めたら config.h に反映する（ユーザーの指示で）。
- ID15 の既知の限界：後方にセンサーがない／狭い場所では一周しても空かないことがある／浅い角度の壁は見つからないことがある。
- ID25 の片側旋回が途中で止められたときは、`[うろうろ] 片側旋回…中断` の行が出る（①ID9に交代、②安全層に止められた）。
  試験の集計では、どちらも「旋回中断」として1つにまとめて数える。後退+その場回転（張りつき対策）が
  途中で交代されたときは別の行・別カウント（`後退回転 実施/中断`）で、優先度35のため通常は一時停止のときだけ出る。
- **`WANDER_SIDE_VERY_NEAR_CM`（25cm）は仮の値**。実機で見回しのログ（横の距離）を見ながら詰める
  （`WANDER_SIDE_NEAR_CM` 40cm との間の使い分けが妥当か）。
- 30°より浅い壁は検知できない（ID25 の見回しと ID26 で対処）。45°の壁は近距離で遠く出る（実測）。
- 電池 7.0V は仮の動作下限（余裕の計算に使った。ID22 で見直す）。走行中の電池電圧の読み取りは乱れる（回転中の 6.40V も同じ可能性。判定には使わない）。
- IR：GPIO0 は起動時のモード選択（strapping）のピン。起動の瞬間にリモコンを押さない。ライブラリは `lib_deps`（初回ビルドはネットワークが必要）。
- 試験の集計はNVS（フラッシュ）に書く。`Preferences` は Arduino-ESP32 のコアに含まれるので `lib_deps` は不要。
  `TestRecord` の構造（`core/test_stats.cpp`）を変えると、保存済みのデータは読み捨てられる（`magic` で判定）。
- **リセット理由**（`hal/hal_reset.*`）は `esp_reset_reason()`（ESP-IDF、`esp_system.h`）のラッパー。
  `Preferences` と同じくコアに含まれるので追加の `lib_deps` は不要。試験は再起動をまたがないので、
  試験を始めるたびに1回だけ刻む（ブート中に値が変わることはない）。
- 作業のコツ：ファイルの作成・編集は Write／Edit ツールで行う。bash のヒアドキュメントは引用符やバックスラッシュで壊れることがあった。
  作業ツリーの改行は CRLF と LF が混在する（Git の自動変換）。Python で直すときは改行を正規化してから置換する。
