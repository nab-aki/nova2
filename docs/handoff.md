## 2. 未解決：後退+その場回転の直後にブラウンアウトで再起動する

**症状**：ID25の後退+その場回転（横がとても近いときの張りつき対策）のあと、車体が動かなくなることがある。
正体は、電圧低下（ブラウンアウト）による意図しない再起動だった（`DEBUG_START_PAUSED`=1のため、
再起動すると一時停止の状態で待っているだけに見える）。`t` の `起動:ブラウンアウト（電圧低下）`で確認済み。
**満充電でも発生する。** キックPWMを出す時間を1000ms→300msに短くしても再発した。

**仮説（コード比較で裏づけ済み）**：ID15（trouble.cpp）は後退の停止から回転開始までに左右確認
（首の安定待ち＋測距3回×2方向。実時間で数百ms、モーター出力0）が自然に入るため再発しない。
ID25の後退+その場回転は、なめらか加減速の出力が0になった同じループ内で即座に回転を始めていた
（`Motion_IsAtTarget()` はソフト上の出力が0になったことしか見ておらず、車体が慣性で
まだ動いているかは分からない）。惰性で回っている車輪を急に逆転させ、大電流が出ていると見ている。

**対策（案B。すでに実装・ビルド済み。書き込み・再試験はこれから）**：新しい状態 `STATE_RECOVER_BACK`→
`STATE_RECOVER_PAUSE`→`STATE_RECOVER_TURN` とし、後退の停止と回転の開始の間に
`WANDER_RECOVER_PAUSE_MS`（500ms、仮の値。config.h）の「ため」を挟んだ（[wander.cpp](src/behaviors/wander.cpp)）。

**それでも再発したら**：`WANDER_RECOVER_PAUSE_MS` をさらに延ばすことをまず試す。それでも治らなければ、
電池・配線の点検（コネクタの緩み・電池の劣化・太い配線への変更）に進む（ソフトでの追加対策は、
決定済みの3案のうち残り2つ＝案B以外の変形、案C＝キックの立ち上がりを段階的にする、が候補）。

## 3. 次にやること（順番）

1. **ブラウンアウト対策（案B）の書き込み・再試験**。手順はシンプルに：
   **ケーブルなしで満充電のまま5分間の試験 → 動かなくなったら（または5分経ったら）止めて `t` を見る。**
   `起動:` が「電源投入」のままならブラウンアウトなし。`ブラウンアウト（電圧低下）` が出たら再発。
2. 再発しなければ、正面衝突0回・張りつき解消・ID9の停止10回以上（完了条件）を満たすか確認し、

3. **回転の値をまとめて見直す**（「片側旋回の値の見直し」に、キック時間短縮による回転角の実測も統合）：
   - その場回転：キック300msでの1ステップの角度を測り直す（`TROUBLE_MAX_STEPS` 12回も見直す）。
   - 片側旋回：保持（1450）がキック（1400）より大きく、キックの意味が薄い（実質 1450 一定）。
   - `WANDER_RECOVER_PAUSE_MS`（500ms、仮の値）も、動きの印象を見ながら詰める。
   - デバッグの調整キー（`3`〜`6`、一時停止中の `q a w s e d r f`）で床の上で探す。
4. ロードマップの次：**ID26 詰まり脱出**（16より前に変更済み。着手時に概要を実測に合わせて見直す）。

## 4. 5分間試験の結果（これまで2回）

- **正面衝突は2回とも0回。** 最優先方針（障害物を避けながらうろうろする）の核心は崩れていない。
- 1回目：張りつき問題（上記「2. 未解決」の前段）。2回目：張りつきは解消したが、ブラウンアウトで再起動。
- **ID9の停止回数は、正しく数えられていない疑いがある（分析済み・未修正）**：`Motion_StartTurn()` が
  速度スムーザーを0にリセットするため、回転中にID9が気づくと `noticedWhileMoving_` が false になり、
  「止まっているときに気づいた」扱いで通算・集計のどちらにも数えられない。回転中の検知がどれだけ
  あったかは、いまのログ・集計からは分からない。ID9の完了条件（停止10回以上）を厳密に判定する前に、
  この数え方を見直すか、影響の大きさを確認する必要がある。

## 6. 未解決の点・注意

- **`DEBUG_START_PAUSED` は 1**（config.h）。起動直後は一時停止で、▶ か `p` で開始する。
  ケーブルなしの試験ではこのまま便利。すぐ動かしたいときは 0 にする。
  試験の集計は、起動時に一時停止のままだと「再開」まで始まらない（1で始まる設定と整合させてある）。
- **書き込みは、ユーザーが指示したときだけ。書き込み前にユーザーがシリアルモニタを閉じる**（COM3 が使用中だと失敗する）。
  書き込みは `~/.platformio/penv/Scripts/pio.exe run -t upload`（fnk0053）。ビルドだけは `pio run`。ホストに g++ はない。
- **持ち上げ中（ライン111）は、`3`〜`6` も受け付けない**（安全層が止める）。床に置いて 111 が消えてから使う。
- 回転キー `3`〜`6` の1ステップの間だけ、障害物「あり」による停止を外している（デバッグ用。非常停止12cm未満と持ち上げは残す）。
  本番の ID25・ID15 は外さない。
- **書き込みで、調整キーで変えた値は元に戻る**。値を決めたら config.h に反映する（ユーザーの指示で）。
- ID15 の既知の限界：後方にセンサーがない／狭い場所では一周しても空かないことがある／浅い角度の壁は見つからないことがある。
- ID25 の片側旋回が途中で止められたときは、`[うろうろ] 片側旋回…中断` の行が出る（①ID9に交代、②安全層に止められた）。
  試験の集計では、どちらも「旋回中断」として1つにまとめて数える。後退+その場回転（張りつき対策）が
  途中で交代されたときは別の行・別カウント（`後退回転 実施/中断`）で、優先度35のため通常は一時停止のときだけ出る。
- **`WANDER_SIDE_VERY_NEAR_CM`（25cm）は仮の値**。実機で見回しのログ（横の距離）を見ながら詰める
  （`WANDER_SIDE_NEAR_CM` 40cm との間の使い分けが妥当か）。
- 30°より浅い壁は検知できない（ID25 の見回しと ID26 で対処）。45°の壁は近距離で遠く出る（実測）。
- 電池 7.0V は仮の動作下限（余裕の計算に使った。ID22 で見直す）。走行中の電池電圧の読み取りは乱れる（回転中の 6.40V も同じ可能性。判定には使わない）。
- IR：GPIO0 は起動時のモード選択（strapping）のピン。起動の瞬間にリモコンを押さない。ライブラリは `lib_deps`（初回ビルドはネットワークが必要）。
- 試験の集計はNVS（フラッシュ）に書く。`Preferences` は Arduino-ESP32 のコアに含まれるので `lib_deps` は不要。
  `TestRecord` の構造（`core/test_stats.cpp`）を変えると、保存済みのデータは読み捨てられる（`magic` で判定）。
- **リセット理由**（`hal/hal_reset.*`）は `esp_reset_reason()`（ESP-IDF、`esp_system.h`）のラッパー。
  `Preferences` と同じくコアに含まれるので追加の `lib_deps` は不要。試験は再起動をまたがないので、
  試験を始めるたびに1回だけ刻む（ブート中に値が変わることはない）。
- 作業のコツ：ファイルの作成・編集は Write／Edit ツールで行う。bash のヒアドキュメントは引用符やバックスラッシュで壊れることがあった。
  作業ツリーの改行は CRLF と LF が混在する（Git の自動変換）。Python で直すときは改行を正規化してから置換する。
