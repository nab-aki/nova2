## 3. 未解決の点

**ジャイロ（スプリント3.5）**

- **【要対策】1回の読み取りで loop を止める時間**：平均 3.78ms・最大 16.94ms（87349回）。最大は I2C だけでは説明できない（8件で約9ms）。
  候補は ReadFifo の中のシリアル出力待ち（回転の記録の締め・ゼロ点補正の経過）と割り込み。未確定。
  16.94ms は 239dps で約4°。第2段階の対策案：①1回に読む件数を減らす（`GYRO_MAX_WORDS_PER_READ` 8→4）／
  ②ReadFifo の中で `Log_Printf` を呼ばず、あとで出す／③FIFO の複数件を1回の通信で読めるか調べる（I2C は 100kHz のまま）／
  ④止める判断を「読んだ直後・同じ loop の Motion_Update の前」に置き、惰性（約9°）を先に引いて止める／⑤読み取りの最大値の原因（ログか割り込みか）を記録して切り分ける。
- **【仮】のしきい値**：ゼロ点補正の平均 ±5dps、飛びの判定（100dps、区間内は標準偏差の8倍）、回り始め・止まったの判定。
  **飛び 156件**（`t` の累計。3軸のどれかで1件前との差が 100dps 以上。m・n の数え方とは別。積算からは外していない）は原因が未確定。
  Z の本物の回転では届かない見込みで、X・Y の衝撃（衝突・段差・キック）か手で動かしたときが候補。時刻・軸・大きさの記録を足して調べる。
- **【未確認】FIFO のまとめ読み**：複数件を1回の通信で読めるかはデータシートで確認できず、1件ずつ読んでいる。
  バスの占有（計算上 約13%）が問題になったら調べる。
- J5・J6 は開放のまま（2026-10-10 確定。見直すきっかけは、ケーブルなしの走行で飛びが増えたとき）。
- **【未実施】PCA9685 の OE ピンの配線の確認**（common_gyro_checklist.md）。
- 加速度は動かしていない。遠心分（計算上 約0.02g）の実測と、段差での空回りの検知は、第2段階以降。
