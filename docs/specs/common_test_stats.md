# 共通部品：試験の集計（v1）

ID には紐づかない共通部品（#0）。ID9・ID15・ID25・安全層（持ち上げ）から集計イベントを受け取り、
5分間の試験などの結果を、ケーブルなしでも後から確認できるようにする。

## 目的

- 実機での試験（狭い部屋を歩かせる、壁の前で立て直させるなど）のたびに、紙に手で数えなくても
  結果が残るようにする。
- 電源を切っても、直近の試験の結果はフラッシュ（NVS）に残る。

## 「1回の試験」の区切り

**再開してから一時停止するまで**を1回とする。起動時に一時停止で始まらない設定
（`DEBUG_START_PAUSED` が0）のときは、起動そのものを最初の試験の開始として扱う。

## 集計項目

| 項目 | 出どころ |
|---|---|
| ID9：気づいて停止した回数（走っているときに気づいた分だけ） | `NoticeBehavior::ReportStop()`、`noticedWhileMoving_` が true の分岐 |
| ID9：停止後の距離が測れなかった回数 | 同上、`Obstacle_LastCm() < 0` のとき |
| ID9：停止後の距離の最小・平均（測れた分だけ） | 同上 |
| ID15：立て直しを始めた回数 | `TroubleBehavior::StartSequence()`（あきらめ後の再挑戦・持ち上げ後の再開も含めて数える） |
| ID15：正面が空いて戻った回数 | `TroubleBehavior::onUpdate()` の `STATE_CHECK`、「空いた」と判定する分岐 |
| ID15：あきらめた回数 | 同上、`steps_ >= TROUBLE_MAX_STEPS` で休みに入る分岐 |
| ID25：片側旋回を実施した回数 | `WanderBehavior::onUpdate()` の `STATE_FACE_FRONT`、片側旋回を始める分岐 |
| ID25：片側旋回が途中で止められた回数 | `WanderBehavior::onStop()`（他の振る舞いに交代）と `onUpdate()` の `STATE_AVOID`
  （安全層に止められた）。どちらも「片側旋回…中断」とログを出す分岐と同じ場所 |
| ID25：後退+その場回転（張りつき対策。25_wander.md）を実施した回数 | 同 `STATE_FACE_FRONT`、後退を始める分岐 |
| ID25：後退+その場回転が途中で交代された回数 | `onStop()` の `STATE_RECOVER_BACK`／`STATE_RECOVER_TURN` 分岐。
  優先度を引き上げてある（25_wander.md）ので、通常は一時停止のときだけ増える |
| 持ち上げを検知した回数 | `safety.cpp` の `WatchLift()`、持ち上げを新たに検知した分岐 |
| 試験の経過時間 | 再開してからの経過（最後に保存した時点まで） |
| 試験が始まったときの、ブートのリセット理由 | `TestStats_Setup()` で読み、試験を始めるたびに記録へ刻む（下記「リセット理由の記録」） |

記録用のAPI（`core/test_stats.h`）は、**一時停止中（記録中でないとき）に呼ばれても何もしない**。
安全層の持ち上げ検知は一時停止中も動くが、一時停止中に持ち上げても集計には数えない。

## 保存（NVS、フラッシュ）

- `src/hal/hal_storage.*` が NVS（Arduino-ESP32 の `Preferences`）への読み書きを薄く包む。
  中身の意味は関知せず、バイト列を保存・読み出し・消去するだけ。
- 直近3回分だけ、リングバッファで保存する（通算は保存しない）。
- **走行中はフラッシュに書かない。** 書き込みのタイミングは3つ、すべて「車体が止まっているとき」
  （`Motion_IsStill()`）だけ：
  1. **一時停止したとき**：ただし、一時停止した瞬間ではなく、なめらかに減速して車体が止まってから
     保存する（一時停止は「記録を止める」だけを即座に行い、保存は次に `Motion_IsStill()` になった
     ループで行う）。
  2. **シリアルの保存キー（`h`）**：走行中に押しても保存せず、「止まってから押してください」と出す。
  3. **止まっている間の30秒ごと**（`TEST_STATS_SAVE_INTERVAL_MS`）：試験の途中で電源が切れても、
     直前の周期保存までは残るようにする。
- 電源が切れて試験が途中で終わった場合、失われるのは**最後の保存以降の分だけ**（走行中の分が
  失われるのは許容する）。試験は再起動をまたがない（起動時に一時停止でなければ、それ自体が
  新しい試験の開始になるため）。

### 「車体が止まっている」の判定

`core/motion.*` の `Motion_IsStill()` を使う（速度・目標速度・回転のいずれも無し）。
`safety.cpp` の `BodyIsMoving()` も同じ関数を使い、判定を複製しない。

### データの持ち方

```
TestRecord（1回分）
  elapsedMs             経過時間（最後に保存した時点まで）
  startResetCode        試験が始まったブートの、起動時のリセット理由（下記）
  stopCount             ID9 停止回数
  stopDistUnknown        うち、距離が測れなかった回数
  stopDistSumCm/MinCm   測れた分の合計・最小（平均は表示時に計算）
  troubleStarts / troubleCleared / troubleGiveups   ID15 開始・空いた・あきらめ
  pivotPerformed / pivotInterrupted     ID25 片側旋回の実施・中断回数
  recoverPerformed / recoverInterrupted ID25 後退+その場回転（張りつき対策）の実施・交代回数
  liftCount             持ち上げ回数

TestStatsStorage（NVSに保存する全体）
  headIndex             現在（最新）の枠（0〜2）
  validCount            意味のあるデータが入っている枠の数（0〜3）
  ring[3]                直近3回分の TestRecord
```

再開のたびにリングを1つ進めて新しい枠を使う（4回前の枠を上書きする）。最新の枠（`headIndex`）は、
記録中（またはまだ保存が終わっていない一時停止直後）は「生きた値」を、それ以外は最後に保存した
値を指す。

## リセット理由の記録（2026-09-22 追加）

**きっかけ**：狭い部屋での再試験で、後退+その場回転のあと1分以上動かなくなった。原因を調べたところ、
▶ を押した直後に動き出した＝一時停止の状態（`DEBUG_START_PAUSED` は1）から再開しただけで、
実際には**電圧低下（ブラウンアウト）による意図しない再起動**が起きていたと分かった（2026-09-22 の decisions.md）。
ケーブルなしの試験では、この「実は再起動していた」に気づく手段がなかったので、記録に残すようにした。

- `src/hal/hal_reset.*`（新規）が `esp_reset_reason()` を薄く包む。起動直後に1回シリアルへ出す
  （`[起動] リセット理由：ブラウンアウト（電圧低下）` など）。
- `core/test_stats.*` が、起動時のリセット理由（`Reset_ReasonCode()`）を覚えておき、
  **新しい試験を始めるたび**（`BeginNewTest()`、`x` で消去して記録を続ける場合も含む）に、
  その試験の `startResetCode` として刻む。試験の途中でブートが変わることはない
  （試験は再起動をまたがないため）。
- `t` の表示・保存時のログの両方に、その試験が「どのリセット理由のブートで始まったか」を出す。
  電源投入・ソフトウェアリセット以外（特にブラウンアウト）が出ていたら、その試験の直前に
  意図しない再起動があったことが分かる。

## シリアル起動時の表示

`setup()` の最初のほうで、リセット理由を必ず1行出す：

```
[起動] Nova スプリント2（ID25 うろうろ・ID15 障害物で困る）
[起動] リセット理由：ブラウンアウト（電圧低下）（電池切れ・電圧低下の疑い。試験の集計にも残ります）
```

電源投入・ソフトウェアリセットのときは、括弧の注記は付かない。

## シリアルキー

| キー | 動作 |
|---|---|
| `t` | 直近3件（新しい順）を表示する。最新の1件は、記録中ならその場の値、そうでなければ最後に保存した値 |
| `h` | いま保存する（止まっているときだけ。走行中は何もしない） |
| `x` | 集計を消去する。5秒以内に2回押して確定（1回目は確認のメッセージだけ出す）。
  記録中の試験があれば、カウントを0・経過時間を0から数え直す（進行中の試験そのものは終わらせない） |

## 使う部品・共通部品

- `src/hal/hal_storage.*`（新規）：NVSへの読み書き
- `src/hal/hal_reset.*`（新規。2026-09-22）：`esp_reset_reason()` のラッパー
- `src/core/test_stats.*`（新規）：集計の本体
- `src/core/motion.*`：`Motion_IsStill()`（新規）

## 完了条件

- 動作：`t` で直近の試験の集計が表示される。一時停止すると、止まってから保存される
  （走行中に保存の行が出ない）。電源を入れ直しても、直前に保存された内容が残る。
- 動作：`x` を1回押すと確認のメッセージが出て、5秒以内にもう一度押すと消去される。
  5秒過ぎると確認は無効になり、もう一度最初から。
- ID9・ID15・ID25・持ち上げの実機試験で、目視で数えた回数とシリアルの集計が一致する。

## 完了条件（リセット理由）

- 動作：起動直後に `[起動] リセット理由：…` が1行出る。ブラウンアウトのときは注記が付く。
- 動作：`t` の各行に「起動:○○」が出て、その試験がどのリセット理由のブートで始まったか分かる。
- 確認：わざと電池を外して電圧を落とし、ブラウンアウトを起こして `ESP_RST_BROWNOUT` になるか
  （安全に再現できる方法があれば。無理をしない）。
