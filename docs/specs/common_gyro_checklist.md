# ジャイロ搭載チェックリスト（LSM6DSV16X）

スプリント3.5「ジャイロ搭載」の着手前に読む。方針の決定は docs/decisions.md（2026-09-27）。

■ 実測済み（2026-09-27）
- IICポートの VCC：3.3V
- SDA/SCL のプルアップ先：3.3V（ESP32 をリセット中に測定）
- アドレスの重なりなし：0x20（PCF8574）、0x5F（PCA9685）、0x71（HT16K33）、ジャイロは 0x6A または 0x6B

■ 実測済み（2026-10-06。モジュール単体・配線後）
- ジャンパーの判定は、モジュールを外して電源なしで端子間の抵抗を測って行った（目視は難しい）。
  約10kΩ ならつながっている、MΩ 以上なら開放。
- 出荷時：J1〜J4 はすべて開放（SA0–GND 開放、SA0–3V3 6MΩ、CS–GND 14MΩ、SDA–3V3 5MΩ）。
- J3（「6A」の刻印側）をはんだで短絡した。SA0–GND が 10kΩ になり、**アドレスは 0x6A**。
- J2：開放　J4（CS–GND）：開放　J1（プルアップ）：開放（バス側のプルアップを使う）
- J5・J6（SDX・SCX）：未確認・未変更（開放のまま。下の「J5・J6 の要否」を参照）。
- 配線に使った端子：ピンヘッダ（Qwiic コネクタは使っていない）。
- 配線した端子の電圧：3V3＝3.3V、SDA＝3.3V、SCL＝3.3V。

■ モジュールの回路（秋月の回路図 AE-LSM6DSV16X_20250113 より。ジャンパーの番号は下の記述と一致）
- 基板にレギュレータ・レベル変換はない。VDD と VIO は同じ 3V3 につながる（**3.3V 専用。5V 不可**）。
- CS は R5（10kΩ）で 3V3 に引き上げ済み。J4 を開放のままにすれば I2C になる。
- 出荷時は J1〜J4 が開放。I2C で使うには **J2 か J3 のどちらか一方のはんだ付けが必須**
  （両方開放だと SA0 が浮き、両方接続だと中間電圧になる）。
- Qwiic ケーブルの色：黒 GND、赤 3.3V、青 SDA、黄 SCL。

■ 取り付け前（ハードウェア）
- ジャンパー
  - J4（CS を GND）：必ず開放。つながっていると I2C が無効になる。
  - J2／J3（アドレス）：どちらか一方だけつなぐ（J3 で 0x6A、J2 で 0x6B）。Nova は J3（0x6A）。
  - J5・J6（SDX・SCX を GND）：つなぐ（理由は下の「J5・J6 の要否」）。
  - J1（I2C プルアップ 10kΩ）：開放（バスは既に 3.3V にプルアップ済み）。
- J5・J6 の要否（ST のアプリケーションノート AN5763 Rev 2、Table 1「Internal pin status」で確認）
  - SDx・SCx は、モード1（センサーハブ・補助SPI・アナログハブ／Qvar を使わない）では
    「Vdd_IO か GND につなぐ」と指定されている。
  - 既定では「プルアップなしの入力」なので、開放のままだと入力が浮く。
    秋月のサンプルが開放のままで動くのは事実だが、指定からは外れている（浮いた入力はノイズを拾い、消費電流が増えることがある）。
  - **結論：固定する前に J5・J6 を短絡して GND につなぐ。** I2C のスキャンと WHO_AM_I の確認は、開放のままで行ってよい。
  - はんだ付けを避ける場合の代わり：IF_CFG（03h）の SHUB_PU_EN を 1 にすると内蔵プルアップが入る。
    ただし電源が落ちると設定が消えるので、はんだ付けのほうが確実。
  - 参考：OCS_Aux・SDO_Aux は「Vdd_IO につなぐか未接続」で、既定で内蔵プルアップつき。対応は不要。
- 取り付け位置：車体の中心付近に水平に。首には載せない。スポンジ入り両面テープで振動を吸収する。
- 配線：20cm 以内。SDA/SCL は GND と束ね、モーター線から離す。振動で抜けないよう固定する。
- 接続：Qwiic（1mm ピッチ）と IICポートをつなぐケーブル、またはピンヘッダーから配線。
- 取り扱い：衝撃と静電気に弱い。
- できれば：PCA9685 の OE ピン（チップの23番ピン）の配線をテスターで確認する（GND 直結か、GPIO につながっているか）。

■ ソフトウェアの設定（データシートより）
- 測定範囲：既定の ±125dps では回転の瞬間に頭打ちになり、回りすぎる。±500dps に設定する。
- ODR：ジャイロは既定で停止状態。ODR を設定する。
- 読み取り方法：loop で最新値だけ読むと間のデータを捨てて角度がずれる。FIFO でまとめて読むか、内蔵の SFLP（姿勢計算）を使う。
- ゼロ点補正：補正後でも約 ±1dps ずれる（放置すると1分で約60°）。起動時の一時停止中に必ず補正する。動いていたらやり直す。
- ノイズ対策：IF_CFG の ASF_CTRL を 1 にして、SCL/SDA のノイズ除去フィルターを常に有効にする。
- WHO_AM_I は 0x70。起動時に確認してログに出す。
- 回転の正の向き：上から見て反時計回り。取り付けの向きに合わせて符号を決める。

■ 秋月のサンプルプログラムの設定と、Nova の設定の違い
（サンプル：秋月電子 2025-12-22 版。レジスタの意味は AN5763 Rev 2 で確認）

| レジスタ | サンプルの値 | 意味 | Nova |
|---|---|---|---|
| CTRL1（10h） | 0b00001001 | 加速度：高性能モード（OP_MODE_XL=000）、ODR 960Hz（ODR_XL=1001） | ODR を下げる（下記） |
| CTRL2（11h） | 0b00001001 | ジャイロ：高性能モード（OP_MODE_G=000）、ODR 960Hz（ODR_G=1001） | ODR を下げる（下記） |
| CTRL6（15h） | 0b00000100 | ジャイロの測定範囲 ±2000dps（FS_G=0100）。換算は 70mdps/LSB（サンプルの係数 0.07 と一致） | **±500dps（FS_G=0010、17.5mdps/LSB）** |
| CTRL8（17h） | 0b10000010 | 加速度の測定範囲 ±8g（FS_XL=10、0.244mg/LSB。サンプルの係数と一致）。上位3ビット HP_LPF2_XL_BW=100 は、CTRL9 の LPF2_XL_EN・HP_SLOPE_XL_EN が 0 のままなので効かない | ±2g か ±4g で足りる見込み（空回り検知で決める） |
| 22h から12バイト | 読むだけ | OUTX_L_G〜OUTZ_H_G（22h〜27h）、OUTX_L_A〜OUTZ_H_A（28h〜2Dh）。各軸16ビット・下位が先・2の補数。連続読みはアドレス自動加算（CTRL3 の IF_INC、既定で有効）に頼っている | FIFO から読む |

- 読み方の違い：サンプルは 100ms ごとに最新値を1回読むだけ（960Hz のうち約1%しか使わない）。
  表示用としては十分だが、角度を積算すると大きくずれる。Nova は FIFO でまとめて読むか、SFLP を使う。
- ODR の違い：960Hz を FIFO で全部読むと、ジャイロだけで毎秒約6.7kバイト（1件7バイト）になり、
  100kHz のバス（毎秒約11kバイト）の半分以上をふさぐ。モーター・首・ラインと共有できない。
  **Nova は 120Hz か 240Hz にする**（120Hz で毎秒約0.8kバイト、バスの約8%。値は実装時に決める）。
- SFLP（内蔵の姿勢計算）を使う場合：EMB_FUNC_EN_A の SFLP_GAME_EN を 1 にする。出力は FIFO からだけ読める。
  SFLP の ODR は 15〜480Hz で、加速度・ジャイロの ODR 以下にする。加速度も動かしておく必要がある。
- サンプルは I2C の失敗を調べていない（endTransmission・requestFrom の戻り値を捨てている）。Nova は捨てずに数える。
- サンプルが触れていない設定で、Nova が追加するもの：ASF_CTRL（IF_CFG の bit5）、BDU（CTRL3）の確認、ゼロ点補正。
- 未確認：FS_G のコード表（0010＝±500dps）そのものは AN5763 の本文で見つけられなかった
  （サンプルの 0100＝±2000dps・70mdps/LSB とは整合する）。実装時に、設定を読み戻し、実際に 90° 回して換算を確かめる。

■ I2C の確認ツール（tools/i2c_scan/。本体とは独立）
- 0x08〜0x77 を2秒ごとにスキャンし、ジャイロの WHO_AM_I（0Fh＝0x70）を読む。100回連続で読んで失敗を数える。
- 読むだけ。PCA9685 にもジャイロにも書き込まないので、モーター・首は動かず、設定も変わらない。
- 期待：0x20・0x5F・0x71・0x6A の4台。0x70 は PCA9685 の All Call で、電源投入直後は応答する（異常ではない）。
- 固定する前に1回、固定して配線を留めたあとにもう1回流す。
- ツールを書き込むと本体のファームは上書きされるので、確認後に本体を書き戻す。

■ 共有バスの対策（条件付きで可とした条件）
1. 速度は 100kHz のまま（PCF8574 の上限）。
2. Wire.setTimeOut() を 5ms 前後に短くする（既定 50ms のままだと、バス異常時にモーター更新が最大約400ms 止まる）。
3. I2C の失敗を機器ごとに数え、t に出す。PCA9685 ライブラリは失敗を捨てているので、最小限の改変（NOVA_PATCH）か直接書き込みで対応する。
4. ジャイロの失敗が続いたら読み取りをやめ、時間ベースの回転に戻る。時間の上限は常に残す（時間ベースの値は削除せず、予備・上限として残す）。
5. PCF8574 が続けて読めないときは、持ち上げを判定できないので止める側に倒す。
6. バスの復帰（SCL 9回）は ESP-IDF が自動で行う。

■ 残るリスク
- 部品や配線の故障で SDA が Low に張りついたままになると、自動復帰でも戻らず、モーターを止める命令が届かない。
  今の3台にもあるリスクで、ジャイロで1台分増える大きさ。OE ピンが GPIO につながっていれば最後の手段になる。

■ パラメータ整理（仮説。角度制御に切り替えたときに確定する）
- 不要になる：回転時間、ms/° 係数、一周のステップ数（ただし予備・上限として残す）
- 自動化できる：キック（回り始めを検知して保持へ切り替え）、止めるタイミングの補正（行きすぎ量を学習）
- 人が決める：回る速さ（見た目の自然さ）
- 変わらない：前進の最低PWM、停止距離、超音波のしきい値、首の安定待ち

■ 搭載後に確かめたいこと
- **段差での空回りの検知**：ID26 の部屋10分試験（2026-09-27）で、車輪が段差に乗り上げて空回りする場面があり、
  見回し不変時間が23.4秒まで伸びた（詳細は docs/specs/26_stuck.md「実機評価」）。車体は実際には動いていないのに、
  超音波の見回しだけでは「動いていない」と気づくのに時間がかかる。ジャイロ（加速度）なら、車輪が回っていても
  車体の姿勢・並進が変化していないことを直接検知できる候補になる。搭載後、空回りを起こして
  加速度・角速度がどう出るかを確かめる。
