# 共通部品：ジャイロの角度で止めるその場回転（スプリント3.5 第2段階。v1）

ID には紐づかない共通部品（#0）。その場回転を、時間ではなくジャイロで測った角度で止める。
時間ベースの値は消さず、予備と上限として残す。

- 状態：**仕様のみ（2026-10-10）。未実装。** 下の「決めること」が決まってから着手する。
- 先に読むもの：[common_gyro_checklist.md](common_gyro_checklist.md)（第1段階の実装）、
  measurements.md「ジャイロ第1段階の実機確認」（午前・午後の2節）、catalog.md のスプリント3.5。
- この文書の数値のうち、実測でないものには【見積もり】【仮】【未確認】を付けた。まとめは最後の「実測でない値と確かめ方」。

## 目的

- 「90°の指示で±10°以内に、10回中9回収まる」（catalog.md の完了条件）。
- 電池の状態や床で回る量が変わらないようにする。今の時間ベースは、設計の約1.5〜1.9倍回っている
  （2026-10-10 の実測。425ms で 42〜67°、1170ms で 143〜173°、1534ms で 220°）。
- ジャイロが使えないときは、今までどおり時間で回る。どちらで回ったかが `t` で分かる。

## 対象と対象外

| 対象 | 内容 |
|---|---|
| 対象 | その場回転（`TURN_ROTATE_LEFT`／`TURN_ROTATE_RIGHT`）。ID15・ID25・ID26・デバッグキー 3・4・7・8 |
| 対象外 | 片側旋回（`TURN_PIVOT_*`。今は使っていない。時間ベースのまま） |
| 対象外 | 直進のまっすぐさの補正、向きの絶対値の利用（ID16 以降で考える）、加速度、空回りの検知 |
| 対象外 | 回る速さを落として止める（PWM を2段階にする）。回り出す最低PWM が未測定なので、今回は PWM2000 のまま |
| 対象外 | FIFO のまとめ読み、ODR・測定範囲の変更。**ジャイロのレジスタ操作は第1段階から変えない** |

## 用語

- **目標角度**：振る舞いが指示する角度。**止まりきったあとの向きの変化**で数える（止めるまで＋惰性）。
- **惰性**：モーターを止めてから、車体が止まるまでに回る角度。
- **止める角度**：モーターを止める判断をする角度。目標角度 − 惰性の見込み。
- **時間の上限**：角度に届かなくても、この時間で必ず止める。

## 動作の流れ

1. 振る舞いが「向き・目標角度・時間ベースの時間」を渡して回転を始める（`Motion_StartTurnDeg()`）。
2. motion が、ジャイロが使えるかを見る（下の「ジャイロが使えないとき」）。
   - 使える：**角度で止める**。時間の上限を決める。
   - 使えない：**時間ベース**（渡された時間で止める。今までと同じ動き）。
3. PWM2000・キックなしで回し始める（今までと同じ）。
4. 回転中は、FIFO を読む間隔を短くする（`GYRO_READ_INTERVAL_TURN_MS` 10ms【仮】。ふだんは 25ms）。
5. FIFO を読んだ直後に、止めるかどうかを判断する（下の「止める判断の場所」）。次のどれかで止める。
   - **角度に届いた**：回った角度 ≧ 止める角度。
   - **回っていない**：直近 `GYRO_TURN_STALL_MS`（300ms【仮】）で進んだ角度が `GYRO_TURN_STALL_DEG`（3°【仮】）未満。
   - **時間の上限**：回し始めてから、時間の上限がたった。
   - **途中でジャイロを失った**：新しい値が `GYRO_TURN_STALE_MS`（60ms【仮】）来ない、FIFO があふれた、読み取りをやめた。
   - **中断**：振る舞いの交代、持ち上げ、非常停止（今までと同じ）。
6. 止めたあとも積算を続け、止まりきったら（第1段階の「止まった」の判定のまま）記録を締める。
   目標との差、止めた理由、止める判断をしたときの角速度、惰性を1行で出す。
7. 振る舞いは `Motion_IsTurning()` が false になったら次へ進む（時間を自分で数えない）。

急発進・急停止をしない（設計原則3）は、今までどおり、回転の前の「ため」で守る。回転そのものの出し方は変えない。

## 1. 止め方：惰性の分を先に引く

### 実測から分かること

| 条件 | 止めるまで | 惰性 | 出どころ |
|---|---|---|---|
| 425ms（午前。左4回・右3回） | 約41°（合計 約50° − 惰性） | 6.6〜11.3°（平均 約9°） | measurements.md 午前 |
| 1170ms（午前。左3回・右3回） | 約147° | 同上（回した時間によらない） | 同上 |
| 425ms（午後。7回） | — | 6.2〜13.1° | measurements.md 午後 |
| 1534ms（午後。1回） | 209.0° | 11.0° | 同上 |

- 惰性は 6.2〜13.1°。中心は約 9.5°、幅は ±3.5°。
- 回した時間（425〜1534ms）で惰性は変わらない。**どの回も、止めた時点でほぼ同じ速さ（約150dps【見積もり】）に達していた**と考えられる。
- **止めた瞬間の角速度は記録していない。** したがって「惰性が角速度に比例するか」は、今のデータでは判断できない。

### 提案：まず固定値で始め、角速度を記録してから決める

止める角度は、次の式で決める。

```
惰性の見込み = GYRO_TURN_COAST_DEG ＋ GYRO_TURN_COAST_PER_DPS × ｜止める判断をするときの角速度｜
止める角度   = max( 目標角度 − 惰性の見込み, GYRO_TURN_MIN_DRIVE_DEG )
```

- 初期値は `GYRO_TURN_COAST_DEG` ＝ 10°、`GYRO_TURN_COAST_PER_DPS` ＝ 0（**固定値と同じ**）。
- 式を2項にしておくのは、あとで config.h の値だけで「角速度に応じて変える」へ切り替えられるようにするため。

固定値で足りると考える理由：

- 今の指示は 30〜210° で、止める角度は 20°以上。回り始めて約 20°進むころには、速さはほぼ上がりきっている【見積もり】。
  つまり、どの指示でも止める瞬間の速さはあまり変わらない見込み。
- 惰性のばらつき ±3.5° は、完了条件の ±10° に収まる（下の「誤差の見積もり」）。

固定値で足りなくなる場面：

- **電池が減って回る速さが落ちたとき**。2026-10-04 は約80dps、今日は約150dps だった。
  速さが半分なら惰性も小さくなるはずで、固定の 10° を引くと手前で止まる（回り足りない）。
- 将来、30°より小さい角度を指示したとき（速さが上がりきる前に止める）。

そこで、段取りの第1歩（下の「実装の段取り」）で**止めた瞬間の角速度と惰性を回転ごとに記録**し、
通し試験と、電池が減った状態の数回で「角速度と惰性の関係」を見てから、比例の係数を入れるかを決める。
物理的には、惰性は「止める指示が効くまでの遅れ × 角速度」と「減速中に進む分」の和になる【推測】。
比例で近似するなら 9.5° ÷ 150dps ≒ 0.063（°/dps）【見積もり】が出発点になる。

### 誤差の見積もり（90°の指示、今日の速さ 約150dps）

| 要因 | 大きさ【見積もり】 | 向き |
|---|---|---|
| 惰性のばらつき（6.2〜13.1°に対して 10° を引く） | −3.8〜+3.1° | 両側 |
| 止める判断の遅れ（最新の値の古さ＋読む間隔 10ms＋読み取り） | 0〜約3° | 回りすぎる側だけ |
| loop が長く止まった瞬間と重なる（最大 約18ms） | 0〜約2.7° | 回りすぎる側だけ |
| 合計 | 約 −4〜+9° | |

- ±10° には入る見込みだが、回りすぎる側の余裕が小さい。
- 判断の遅れは毎回ほぼ同じだけ出るので、`GYRO_TURN_COAST_DEG` を実測で直せば吸収できる
  （確認用のキーが、差の平均から「この値にすると差の平均が0に近づく」を出す）。
- 第1段階の「惰性」は止める指示の時刻から測っているので、判断の遅れは含まれていない。初期値 10° は実測の平均（約9〜9.5°）に少し足した値。

## 2. 止める判断の場所と、loop を止める時間

### 判断の場所

loop の順番を次のようにする（★が新しい・変える所）。

```
Sensors_Update
Gyro_Update            … FIFO を読んで角度を積算する。★この中では Log_Printf を呼ばない
★Motion_UpdateTurn     … 回転中だけ。止める判断をし、止めるならここで Motor_Stop() まで行う
GyroMeasure_Update / Neck_Update / Obstacle_Update
Arbiter_Update / Safety_Update
Eyes_Update
Motion_Update          … 今までどおり（キック→保持の切り替え、直進の出力）
Trace_Update / TestStats_Update
★Gyro_PrintPending     … ため込んだジャイロのログを出す。★回転中は出さない
状態行（1秒ごと）       … ★回転中は出さず、回転が終わってから出す
```

- 止める判断から Motor_Stop() までの間に、シリアル出力・振る舞い・安全層の処理を挟まない。
- motion が判断し、gyro は「回し始めてからの角度・いまの角速度・最新の値の時刻・使えるか」を返すだけにする
  （gyro がモーターを直接止めない。ハードウェアの操作は hal を通す、の決まりも変わらない）。
- 「[動き] その場回転 左 停止」のログは、Motor_Stop() のあとに出す（今までと同じ順）。

### ReadFifo の中でログを出さない

今は ReadFifo の中から、次のログが出る。すべて「記録だけ残して、あとで出す」に変える。

| いまログを出している所 | 変更後 |
|---|---|
| 回転の記録の締め（`FinishTurn`） | 記録（構造体）をためて、loop の最後に出す |
| ゼロ点補正の完了・やり直し（`CalAdd`） | 同上 |
| FIFO があふれた | 回数を数え、loop の最後に1行 |
| 読み取りをやめた（`NoteFail`） | 状態だけ変え、loop の最後に1行 |

### 最大値の原因（いまの見立て）

- 1回の読み取りは、I2C だけなら最大 約9ms【計算】（件数の確認 約0.5ms＋1件 約1ms × 上限8件）。実測の最大は 16.94ms・18.03ms。
- **有力な候補はシリアル出力の待ち**。この環境（Arduino-ESP32 2.0.17）は、`Serial` の送信バッファが既定で 0 で、
  UART の 128 バイトの FIFO に入りきらない分は、送り終わるまで書き込みが戻らない
  （フレームワークのソースで確認：`HardwareSerial.cpp` の `_txBufferSize(0)` と、`setTxBufferSize()` のコメント）。
  回転の記録の1行は 約240バイト【見積もり】なので、115200bps では (240−128) ÷ 11.5 ≒ 約10ms 待つ【計算】。
  これに I2C の 4〜8ms を足すと 14〜18ms で、実測の最大と合う。ケーブルなしでも送信は行われるので、午後の結果とも矛盾しない。
- ただし**まだ確定ではない**（割り込み・別タスクの可能性は消えていない）。下の記録で切り分ける。

### 切り分けのための記録（`t` に出す。起動からの累計）

| 記録 | 内容 | 分かること |
|---|---|---|
| loop 1周の時間 | 平均・最大。全体と「回転中だけ」を別に | 回転中に長く止まることがあるか |
| 区間ごとの最大 | センサー／ジャイロ／回転の判断／振る舞い／安全／動き／ログ・状態行 | どこで時間を使ったか |
| ReadFifo の内訳 | 最大のときの「読んだ件数・I2C に使った時間・それ以外の時間」 | I2C か、それ以外（割り込みなど）か |
| ログ出力の時間 | `Log_Printf` 1回の最大・2ms を超えた回数・そのときのバイト数 | シリアルの待ちが原因か |

- ReadFifo の中でログを出さなくしたあとも ReadFifo の最大が 10ms を超えるなら、原因は割り込み・別タスク側と分かる。
- ログ出力の最大が 約10ms なら、見立てどおり。対策は「決めること」の D4（送信バッファを持たせる）。

### 読む件数と間隔

- 1回に読む件数の上限 `GYRO_MAX_WORDS_PER_READ` は 8 → **4**（1回の読み取りを I2C だけで 約5ms 以下にする【計算】）。
  読み残しは次の loop で続けて読む（今の仕組みのまま）。
- 回転中は読む間隔を 25ms → 10ms【仮】にする。1回に読むのは1〜2件になり、判断の遅れが 約25ms → 約10ms に縮む。
  バスの占有は、回転中だけ 約13% → 約15%【計算】（件数の確認が毎秒40回 → 100回）。PCA9685 への書き込みは回転中ほとんどないので、支障はない見込み。

## 3. 時間の上限と「回っていない」の検知

角度に届かない場面（空回り、押さえられた、電池切れ、ジャイロが実際より小さく読む）でも、必ず止まるようにする。2段で守る。

### (a) 時間の上限

**提案：今の時間ベースの値を、そのまま上限にする**（`GYRO_TURN_LIMIT_RATIO` ＝ 1.0）。

| 指示 | 時間ベースの値（＝上限） | 今日の速さで角度に届く時間【見積もり】 | 2026-10-04 の速さで届く時間【見積もり】 |
|---|---|---|---|
| 30° | 425ms | 約290ms | 約300ms |
| 90° | 1170ms | 約700ms | 約1110ms |
| 210° | 2730ms | 約1510ms | 約2610ms |

- 今の値は、2026-10-04 の遅い状態（約80dps）で「ちょうど設計の角度まで回る時間」。
  つまり上限としては「10/04 の状態までは角度に届き、それより遅くなると届かずに時間で止まる」になる。
- 届かずに止まった回数は `t` に出る。増えてきたら電池が減った合図になる。動きは今の時間ベースと同じ（回り足りない）で、危なくはない。
- 上限まで回ってしまったとき（ジャイロが小さく読んでいる場合）の回りすぎは、今日の速さで設計の約1.8倍。**今の動きと同じ**で、それより悪くはならない。
- 上限を長くする案（×1.3 など）は、電池が減っても角度に届きやすくなる代わりに、ジャイロが小さく読んだときの回りすぎが増える
  （×1.3 だと 90°の指示で最大 約220°【見積もり】）。「決めること」D3。

### (b) 回っていないときは早く止める

- 直近 300ms【仮】で進んだ角度が 3°【仮】未満なら、「回っていない」として止める。
  回り始めの実測は 20〜70ms なので、300ms は約4倍の余裕。
- 押さえられた・壁に引っかかった・電池切れで回らない、のどれでも、PWM2000 を出し続ける時間が最長 300ms で済む
  （今は最長 2730ms 出し続ける。電池の落ち込みが大きい動きなので、早く止める意味がある）。
- 「ジャイロが壊れて 0 を返し続ける」ときも、ここで止まる（実際には回っていても 300ms で止まるので、回りすぎない）。
- 止めたあとは、振る舞いは「回転が終わった」として次へ進む（今、時間で止まったときと同じ）。回数は `t` に出す。

## 4. ジャイロが使えないとき

| 場面 | 判定 | 動き |
|---|---|---|
| 回し始めるときに使えない | ゼロ点が未補正／状態が「測定中」でない（未検出・設定中・補正待ち・補正中・停止）／角度制御を切ってある | その回転は**時間ベース**（渡された時間で止める。今までと同じ） |
| 回転の途中で失った | 新しい値が 60ms【仮】来ない／FIFO があふれた／読み取りをやめた | **その場で止める**（回り足りない側に倒す）。次の回転からは時間ベース |
| 頭打ち（±500dps の端） | その回転で頭打ちが1件でもあった | 止め方は変えない。記録に件数を出す（実測の最大は 239dps で、余裕がある） |

- 途中で失ったときに時間ベースへ切り替えないのは、残り時間を正しく決められないため（時間ベースは今、設計の1.5〜1.9倍回る）。
  回り足りなくても、ID15 は測り直してもう1回回るし、ID25・ID26 も次の見回しでやり直せる。
- 読み取りをやめたあとの復帰は、今までどおり `z` キー（自動では復帰しない）。
- `t` に出すもの：
  - いまの止め方：`回転の止め方：角度（ジャイロ）` または `時間ベース（理由：ゼロ点 未補正）` のように、理由つきで1行。
  - 回数（起動からの累計）：角度で止めた／時間の上限で止めた／回っていないので止めた／時間ベースで回した（理由ごと）／途中でジャイロを失った／中断。
- 止め方が切り替わったとき（角度 → 時間ベース、またはその逆）は、その場でも1行出す。
- 試験の集計（NVS に残す直近3回分）へ入れるかは「決めること」D8。

## 5. 飛びの扱い

- **値は捨てない。数えるだけ**（今までどおり、積算にそのまま足す）。
  走行中に約18件/分出ており（午後の実測）、本物の動き（衝撃・段差）である可能性が高い。捨てると角度が合わなくなるおそれがある。
- 直近 8件【仮】について、次を残して `t` に出す：時刻、軸、1件前の値 → 今の値、そのときの車体の動き（停止／前進／後退／回転／一時停止中）。
- 回数を、軸ごと（X／Y／Z）と、車体の動きごとに分けて数える。
  **回転中の Z 軸の飛びが0件なら、回転の角度には影響していない**と言える。0件でなければ、その大きさを見て扱いを決める。
- しきい値（100dps）は【仮】のまま。上の記録を見てから決める。

|---|---|---|---|

| ID25 横が近いときの向き変え | 30° | 425ms | 同上 |
| ID25 後退+その場回転 | 30° | 425ms | 同上 |
| ID26 脱出の回転 | 60〜120°（ランダム） | 780〜1560ms | 約105〜225°【見積もり】（118°のつもりの1回が 220°） |
| ID26 くり返し詰まったとき | 150〜210°（ランダム） | 1950〜2730ms | 約280〜400°【見積もり】 |

- 2026-10-04 に値を決めたときは、設計どおり（12回で一周、1170ms で約90°）だった。今日は約1.5〜1.9倍。
- **2026-10-05 の通し試験（合格）がどちらの状態だったかは分からない**（回った角度も電池の電圧も記録がない）。
  今日の午後の試験（動きは良好、あきらめ0）は、大きく回る状態での結果。
- それより前の試験（2026-09-23、09-27）は、その時点の測り直しで約30°に合わせた直後のもの。

### 選択肢

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| A 設計の角度のまま | 30°／60〜120°／150〜210° | 仕様・過去の検討（12回で一周、「壁沿いに飽きて向きを変えた」程度）と合う。ID26 のくり返しが一周を超えない | 今日より回る量が減る。ID15 は空くまでの回数が増え（1回ごとに回転・待ち・測り直しで 約1秒【見積もり】かかる）、ID25 の向き変えが足りず浅い壁へ戻るかもしれない |
| B 実際に回っていた角度に合わせる | 50°／105〜225°／280〜400° | 今日の動きをそのまま保てる | ID26 のくり返しが一周を超える（意図していない動き）。ID15 の「12回で一周」が崩れる（600°）。「360°近い回転」の再発要因になる |
| C 場所ごとに決める | ID15・ID25 は 45°（ID15 の最大回数は 8回＝360°）、ID26 は設計のまま | 小さい回転は今日の動きに近く、大きい回転は設計に戻る | 45° の根拠は「今日の動きが良かった」だけ。値を2回決め直すことになるかもしれない |

**おすすめは A で始める。** 角度が毎回同じになってから通し試験で数字を比べ、足りなければ角度を上げる（C へ寄せる）。

- 理由1：角度制御の目的が「指示どおり回る」なので、まず設計の値で動きを見るのが筋。
- 理由2：B の ID26（最大 400°）は明らかに意図と違う。
- 理由3：角度は config.h の値になるので、試験のあとで変えるのは簡単（書き込み1回）。
- 比べる数字：困る（ID15）の「開始」に対する回転の回数とあきらめ、うろうろの後退回転の回数、詰まりの「くり返し」の回数、5分間の印象。
  今日の午後（開始19／空き18／あきらめ0、後退回転10、詰まり A2）が比較の基準になる。

## 7. 確認用のキー

| キー | 動き |
|---|---|
| `9` | 左へ 90° を10回くり返し、まとめを出す |
| `0` | 右へ 90° を10回くり返し、まとめを出す |
| `k` | 角度制御の入・切を切り替える（切ると時間ベース。起動時は config.h の `GYRO_TURN_ANGLE_CONTROL`） |

- `9`・`0` は一時停止中だけ受け付ける（キー 7・8 と同じ条件）。どのキーでも、リモコンの ▶ でも中断する。持ち上げでも止まる。
- 1回ごとに「回す → 止まりきるまで待つ → `DEBUG_TURN_TEST_PAUSE_MS`（700ms【仮】）休む」。同じ向きに10回回る（合計 900°）。
  **4回目と8回目で、床の印に戻る**。ジャイロの角度だけでなく、目でも確かめられる。
- 途中でジャイロが使えなくなった回は「時間ベース」と表示し、合否の数から外す。
- まとめの例（measurements.md に貼れる表で出す）：

```
| 回 | 目標 | 回った角度 | 差 | 判定 | 止めた理由 | 止めたときの角速度 | 惰性 |
| 1 | +90.0 | +93.2 | +3.2 | ○ | 角度 | 151dps | 10.9° |
…
| まとめ | ±10°以内 9/10 → 合格 | 差の平均 +2.1°・標準偏差 3.0° | 惰性の平均 11.2° | GYRO_TURN_COAST_DEG を 12 にすると差の平均が0に近づく |
```

- キー 3・4（30°）と 7・8（90°）も角度で止まるようになる。1回ごとの記録に、目標との差が出る。
- 合否はジャイロ自身の角度で数える。ジャイロの換算は第1段階で確かめてある（12回で約600°が目視と一致）が、
  完了の判定では、**床の印とのずれも合わせて見る**（8回で2周したときに、印から大きくずれていないこと）。

## 8. 止まっている間のゼロ点の取り直し

実測：角度のずれは、起動 約5分後に −0.12°/分、約35分後に −0.29〜−0.32°/分。ゼロ点 Z は午前 −0.186、午後 −0.189dps。

- −0.3°/分は 0.005dps。1回の回転（長くて約3秒）では 0.015° で、**回転の角度にはまったく効かない**。
  回転は毎回「回し始めてからの角度」を数えるので、ずれはたまらない。
- 効くのは、向きを長い時間ためて使うとき（「さっき向いていた方へ戻る」など）。第2段階では使わない。

**提案：第2段階では取り直さない。止まっている間のゼロ点を「測って記録するだけ」にする。**

- 車体が 3秒【仮】以上止まっている間、240件の平均を取り、今のゼロ点との差を記録する（直近の差・最大の差・回数を `t` に出す）。
  ゼロ点は書き換えない。
- 理由1：必要がない（上の計算）。
- 理由2：取り直しには失敗の余地がある。止まっているつもりで、首が動いている・人が触れている・床が揺れている間に取ると、
  かえって悪いゼロ点が入る。今は補正のたびに向きの積算を 0 に戻すので、将来 向きを使うときに困る。
- 理由3：記録があれば、ID16 以降で向きを使うことになったときに、取り直しの要否としきい値を実測で決められる。
- 起動時の補正と `z` キーは今までどおり。

## 使う部品・共通部品

- `src/core/gyro.*`：回し始めてからの角度・角速度・最新の値の時刻・使えるかを返す。ログをためて後で出す。飛びの記録。ゼロ点の観察。
- `src/core/motion.*`：`Motion_StartTurnDeg()`、止める判断（`Motion_UpdateTurn()`）、時間の上限、止めた理由と回数。
- `src/behaviors/`：trouble（ID15）・wander（ID25）・stuck（ID26）・debug_turn（キー）。時間を自分で数えるのをやめ、角度を渡す。
- `src/hal/hal_log.*`：ログ出力にかかった時間の記録（D4 を採るなら送信バッファも）。
- `src/main.cpp`：loop の順番、区間ごとの時間の記録、キー `9` `0` `k`。
- 安全層・首の調停・障害物の判定は変えない（その場回転は障害物で止めない、持ち上げは止める、の規則もそのまま）。

## 既知の限界（v1）

- 止める瞬間の速さが大きく変わると（電池の低下）、固定の惰性では目標からずれる。段1の記録で比例の要否を決める。
- 車輪が空回りして車体が回らないとき、「回っていない」で止まるが、向きは変わっていない。振る舞い側は気づかない
  （ID15 は測り直すので実害は小さい。ID26 は次の見回しに任せる）。
- 回転中に車体が押されて余分に回った分は、ジャイロが測るので角度には入る。
- ジャイロが実際より小さく読む故障（換算のずれなど）は、時間の上限まで回る。今の動きと同じ量で止まる。
