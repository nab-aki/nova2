# 共通部品：足あと（直前の動作の記録）（v1）

ID には紐づかない共通部品（#0）。振る舞い・状態が変わるたびに RTCメモリ へ記録し、
ブラウンアウト（電圧低下）で落ちたときに「**何の動作中に落ちたのか**」を次の起動で読み出す。

## きっかけ

2026-09-22 の5分間試験で、後退のあとにブラウンアウトで再起動した。しかし試験の集計（NVS）は
「走行中はフラッシュに書かない」（common_test_stats.md）ため、落ちた回の集計は保存前に消えており、
残った3件はどれも「ID25 後退回転 実施0回」だった。**リセット理由だけでは、落ちた瞬間に何をしていたかが分からない。**
NVS は走行中に書けないので、走行中でも書ける別の置き場所（RTCメモリ）に「足あと」を残すことにした。

## 記録する内容

1件につき、次を残す（`TraceRecord`）。

| 項目 | 意味 |
|---|---|
| 振る舞い名 | そのときの車体の振る舞い（うろうろ・気づく・困る・デバッグ回転・なし） |
| 状態名 | その振る舞いの中の状態（後退・ため（回転前）・その場回転 など）。振る舞いの交代は「交代」 |
| 入った時刻 | その状態に入った時刻（millis） |
| 生きていた時刻 | その状態で最後に生きていたことを確かめた時刻（millis）。下記のとおり刻み直す |
| モーターの出力 | 直進なら「速度→目標」、回転中なら「回転の種類＋生PWM」 |

直近 `TRACE_MAX_RECORDS`（8件）をリングバッファで残し、古いものから上書きする。

## 記録する場所（呼び出し元）

| いつ | どこ |
|---|---|
| 車体レイヤーの振る舞いが交代したとき | `core/arbiter.cpp` の `Arbiter_Update()`（`LAYER_BODY` のときだけ） |
| ID25「うろうろ」の状態が変わったとき | `behaviors/wander.cpp` の `ChangeState()` |
| ID15「困る」の状態が変わったとき | `behaviors/trouble.cpp` の `ChangeState()` と `StartSequence()`（ここは `ChangeState` を通らないため） |
| 生存とモーター出力の刻み直し | `main.cpp` の `loop()` → `Trace_Update()`（`TRACE_ALIVE_INTERVAL_MS` ごと） |

**目レイヤーは記録しない。** まばたきが2〜6秒ごとに変わるので、8件のリングが目の記録で埋まり、
肝心の車体の流れが押し出されてしまうため。

## なぜ「生きていた時刻」とモーター出力を刻み直すのか

- **落ちた時刻が分かる**：記録するのは状態に入った瞬間だけなので、それだけでは「入った直後に落ちたのか、
  1秒後に落ちたのか」が分からない。`Trace_Update()` が 50ms ごとに最新の記録へ時刻を刻み直すので、
  「その状態に入ってから何ms後まで動いていたか」が残る。
- **回転中の出力が正しく残る**：回転は `Motion_SetSpeed()` を通らず生PWMで出すため、直進の目標速度は0のままになる
  （ID9 の停止回数の数え方と同じ落とし穴。decisions.md 2026-09-22 #9）。回転中は `Motion_GetTurnPwm()`
  （キック中はキックPWM、そのあとは保持PWM）を刻むので、電流を最も食う瞬間が記録に残る。
- **呼ぶ順番に左右されない**：`Motion_StartTurn()` と `ChangeState()` の順番は場所によって違う
  （wander は回転開始が先、trouble は状態変更が先）。50ms ごとに刻み直せば、どちらでも実際の出力が残る。

## RTCメモリに残る根拠（ESP32の仕様。2026-09-22 確認）

`RTC_NOINIT_ATTR` を付けた変数は、起動時に初期化されない領域に置かれ、**電源が入ったままの再起動
（ソフトリセット・ウォッチドッグ・ブラウンアウト）では内容が保持される**。確認した根拠：

1. **置き場所**：`esp_attr.h` は `RTC_NOINIT_ATTR` を `.rtc_noinit` セクションと定義し、
   「keep its value after restart or during a deep sleep / wake cycle」と書いている。
   `sections.ld` は `.rtc_noinit` を `(NOLOAD)`（起動時に書き換えない）で `rtc_data_location` に置き、
   `memory.ld` は `REGION_ALIAS("rtc_data_location", rtc_slow_seg)`（`CONFIG_ESP32_RTCDATA_IN_FAST_MEM` 未設定のため）
   としている。`rtc_slow_seg` は `0x50000000 + 512`（先頭512バイトはULP用に予約）・長さ `0x2000 - 512` ＝ 7680バイト。
   実際のビルドでも `.rtc_noinit` は **0x50000200・632バイト**（`objdump -h` で確認）に置かれた。
2. **どちらのCPUからも触れる**：RTC **スロー**メモリ（0x50000000〜）は両方のCPUから読み書きできる。
   RTC **ファスト**メモリ（0x3ff80000〜）は PRO CPU だけだが、今回はスロー側なので問題ない
   （Arduino の `loop()` は APP CPU＝Core1 で動くため、ここは確認が要る点）。
3. **ブラウンアウトでも保持される**：sdkconfig は `CONFIG_ESP32_BROWNOUT_DET=y`・`_LVL=0`。
   `esp_system.h` は `ESP_RST_BROWNOUT` を「Brownout reset (software or hardware)」と定義しており、
   ソフト経路ではブラウンアウト割り込みのハンドラが `esp_reset_reason_set_hint(ESP_RST_BROWNOUT)` を
   呼んでから再起動する。このヒントの置き場所は `system_internal.h` に
   「The hint is stored in RTC store register, RTC_RESET_CAUSE_REG」とある＝**RTCドメイン**である。
4. **実機での裏づけ（いちばん強い根拠）**：この機体では `t` に「起動:ブラウンアウト（電圧低下）」が出ている。
   これは *落ちる直前に RTCドメインへ書かれたヒント* が再起動後も読めているということなので、
   **この機体で起きているブラウンアウトでは RTCドメインの内容は消えていない**。足あとも同じドメインに置く。

**残らない場合**：電池を外すなど電源を完全に切ると内容は不定になる（リセット理由も「電源投入」になる）。
そのため `magic`（"TRC1"）と件数の範囲で「意味のあるデータか」を必ず確かめ、壊れていれば「記録はありません」と出す。
深い電圧低下でRTCメモリまで壊れた場合も、同じ判定で弾かれる（文字列の終端も強制する）。

## NVSへの退避（ケーブルなしの試験のため。2026-09-22 追加）

RTCメモリから取り出した控えは **RAM** に置くので、**次のリセットで消える**。ケーブルなしの試験では、

1. 走行中にブラウンアウト → 再起動（`DEBUG_START_PAUSED`=1 なので一時停止で待つ）
2. ここでケーブルをつなぎ、**シリアルモニタを開くと DTR/RTS で本体がリセットされる**
3. その起動では RAM の控えは消えており、RTCリングも空（一時停止中は車体の状態遷移が起きないため）

となり、`t` を押したときには**落ちた回の足あとが残っていない**。そこで、

- **リセット理由がブラウンアウトのときは、起動直後（モーターが止まっていて、走行中でない間）に
  NVS へも写す**（`STORAGE_KEY_TRACE`）。電源を切っても残る。
- `t` は、NVSに保存された足あとがあればそれを出す（なければ RAM の控えを出す）。
- **`x`（試験の集計の消去）で、保存された足あともいっしょに消える。** それまでは何度でも `t` で読める。
- 取り出した記録が0件のときは写さない。一時停止のまま2回目のブラウンアウトが起きても、
  前に保存した「落ちた回」の記録を空で上書きしないため。

**なぜ一時停止中の記録に押し出されないか**：起動時に RTCリングは必ず空にする（控えへ移す）ので、
再起動後に増える記録は落ちた回の足あととは別の場所に書かれる。リングの8件を食い合うことはない。

補足：`platformio.ini` に `monitor_dtr = 0` / `monitor_rts = 0` を足せばモニタを開いてもリセットされないが、
端末や設定に依存するので、NVSへの退避を正とする。

## 保存データが「古い」ことが分からない問題（2026-09-23 発見・修正）

**症状**：ブラウンアウトが起きていない試験（`起動:電源投入`）のあとで `t` を押すと、
「保存してある『落ちる直前の流れ』（起動:ブラウンアウト）」が出た。中身の時刻が今の試験に近く見え、
一見「たった今落ちた」ように見えたが、実際は**別のブート**（おそらく直前の書き込み時、esptoolの
「Hard resetting via RTS pin」による一瞬の電圧の揺れが本物のブラウンアウトとして検知され、そのとき
RTCリングに残っていた記録がそのままNVSへ保存されたもの）だった。

**原因**：`Trace_Print()`（`t` が呼ぶ）は `hasSaved`（NVSに何か保存されているか）だけを見ており、
**今回の起動自身がブラウンアウトかどうかを見ていなかった**。保存データは `x` を押すまで自動で消えない
（上記のとおり意図的な設計）ため、一度どこかでブラウンアウトが起きると、以降何回ノーマル起動しても
同じ古い記録を出し続けていた。

**対策（案A）**：`Trace_Setup()` で「今回の起動自身がブラウンアウトか」を覚えておき、`Trace_Print()` で
保存データを出すときにこれを見る。今回がブラウンアウトでなければ、見出しのあとに
「※これは以前の起動で保存された記録です。今回の起動はブラウンアウトではありません」ともう1行出す。
あわせて、保存した記録の**最後の時刻**も見出しに出し、どの走行のものかを経過時間と見比べられるようにした。
**保存・消去のタイミング（`x` まで残る）自体は変えていない**。表示だけで、今回の起動と無関係な
データであることが分かるようにした。

## 使い方（表示）

- **起動時**：リセット理由がブラウンアウトのときだけ、「落ちる直前の流れ」として自動で出す（同時にNVSへ写す）。
- **`t` キー**：試験の集計に続けて足あとを出す。保存されたもの（落ちた回）があればそれを優先し、
  なければ前回の起動の分を出す。
  - 見出しに、保存した記録の**最後の時刻**（例：`最後の記録の時刻513709ms`）を出す。
    どの走行のものかを、今の試験の経過時間と見比べて判断できるようにするため。
  - **保存されたものを出すときは、今回の起動がブラウンアウトかどうかも見る。** 今回がブラウンアウト
    でなければ「※これは以前の起動で保存された記録です。今回の起動はブラウンアウトではありません」と
    もう1行出す（2026-09-23 追加）。**保存データ自体は今までどおり `x` を押すまで残る**（消す・消さないの
    動作は変えていない。今回の起動と無関係なデータであることを、表示の側で分かるようにしただけ）。
- **`x` キー**：試験の集計といっしょに、保存された足あとも消す（5秒以内に2回押して確定）。

```
[足あと] 落ちる直前の流れ（8件。時刻は前回の起動からの millis。古い順）
[足あと]   6) 41230ms うろうろ／後退 速度-0.20→-0.20（812ms続いた）
[足あと]   7) 42042ms うろうろ／ため（回転前） 速度0.00→0.00（500ms続いた）
[足あと]   8) 42542ms うろうろ／その場回転 その場回転 左 PWM1600（175ms続いた） ←ここで途切れた
```

最後の行の「続いた」時間が、その状態に入ってから落ちるまでの時間（最大で `TRACE_ALIVE_INTERVAL_MS` の誤差）。

## 使う部品・共通部品

- `src/hal/hal_trace.*`（新規）：RTCメモリのリングバッファ（置き場所だけを受け持つ）
- `src/core/trace.*`（新規）：何を記録するか（モーターの出力の読み方）と、表示・NVSへの退避
- `src/hal/hal_storage.*`：NVSへの読み書き（キーを引数に取る形に変更。試験の集計と共用）
- `src/core/motion.*`：`Motion_GetTurnPwm()`（新規。いま回転に出しているPWM）
- `src/core/arbiter.*`・`behaviors/wander.*`・`behaviors/trouble.*`：記録の呼び出し元
- `src/hal/hal_reset.*`：起動時に出すかどうかの判定（ブラウンアウトか）

## 調整パラメータ（config.h）

| TRACE_TEXT_LEN | 28 | 振る舞い名・状態名の長さ（UTF-8。日本語9文字ぶん。文字の切れ目で詰める） |
| TRACE_ALIVE_INTERVAL_MS | 50 | 「ここまで生きていた」と出力を刻み直す間隔 |

## 完了条件

- 動作：`t` で足あとが出る（電源を入れ直した直後で保存もなければ「記録はありません」）。
- 動作：わざと電源を切らずにリセット（`p` で一時停止→リセットボタン、または書き込み）した後、
  直前の状態の並びが読める。
- **動作：ケーブルなしの試験でブラウンアウトが起きた後、ケーブルをつないでモニタを開き
  （＝もう一度リセットされる）`t` を押しても、落ちた回の足あとが読める。**
- 動作：`x` を2回押すと、保存された足あとも消える。
- 実機：ブラウンアウトが再発したとき、最後の記録が後退〜その場回転のどこを指しているかが分かる。
