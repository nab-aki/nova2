# ToF 搭載チェックリスト（VL53L8CX）

スプリント3.6「ToF（VL53L8CX）」の着手前に読む。方針の決定は docs/decisions.md（2026-10-12・2026-10-21）。
センサー（Pololu #3419）は購入済み・到着済み。配線と首の上への仮固定まで済んだ（2026-10-21 までにユーザーが実施）。
ソフトは単体試験の環境をビルドしただけで、実機ではまだ何も確かめていない（2026-10-24 時点）。

■ 取り付けの変更（2026-10-21。decisions.md）
- **ToF は首の上端（床から約12.5cm）に付ける。超音波は車体の前に固定し、正面だけを見張る。**
  （2026-10-12 の当初の案は「ToF を正面に固定、超音波は首」。下の「決めたこと（2026-10-12）」の取り付けの行は、この変更で置き換わった）
- 理由：ToF の向きをサーボで変えられる。正面の見張りが首の向きや遅れ（約10回に1回、約0.5秒。common_neck.md）に左右されなくなる。
  首を走行中も表情に使える。
- 課題：ToF の線が 8cm を超え、首の動きで曲がる。見回しが ToF 頼みになる（ToF が使えないときの動きを決める必要がある）。
- 3段階で進める。うまくいかなければ、ToF を前に固定する当初の案に戻る（戻る場所は注釈付きタグ `before-tof`＝0a3122b）。
  - **3.6-1** ToF を首の上に仮付けして、単体で測る（超音波は首のまま。本体のソースは変えない）。← いまここ
  - **3.6-2** 超音波を車体の前に移し、止まる距離を測り直す。
  - **3.6-3** 見回しを ToF に切り替え、ToF が使えないときの動きを決める（Opus 5 で行う。このときブランチを作る）。

■ 決めたこと（2026-10-12）
- 目的：浅い角度の壁への接触を減らす（2026-10-12 の5分うろうろで、目視で約4回）。超音波は浅い角度の壁から反射が戻らない。
- カメラを外し、VL53L8CX を1台付ける（当初は正面に固定。2026-10-21 に首の上端へ変更）。基板は Pololu #3419。
- つなぎ方：**I2C。第2バス（Wire1）、SDA＝GPIO26、SCL＝GPIO27**（カメラの SIOD・SIOC だったピン）。
  今のバス（Wire、GPIO13・14）には載せない。
- Pololu #3419 は既定が SPI なので、**基板の SPI/I2C のピンを GND につなぐ**（I2C にする。Pololu #3419 の製品ページより）。
- ライブラリ：STM32duino VL53L8CX 2.1.0（https://github.com/stm32duino/VL53L8CX）。lib/ に取り込んで、下の「組み込みの前の条件」を直す。

■ 回路図で確認したこと（2026-10-12。相談チャットで Freenove の Datasheet/ESP32_Schematic.pdf
〔ESP_CAM_PRO_v1.4、2020-07-21〕を画像にして確認）
- GPIO26・27 は、ESP32 基板の上でカメラの I2C_SDA・I2C_SCL として **10kΩ（R6・R7）で 3.3V にプルアップ済み**。
- カメラのピンは全部、ESP32 基板のヘッダー P3・P4 に出ている。
- P3 のピン番号：P3-1＝3V3、P3-10＝GPIO26、P3-11＝GPIO27、P3-14＝GND（下の「配線の計画」で使う）。
- 3.3V のレギュレータは AMS1117。
- GPIO0 は起動ボタンと自動リセットに使われ、カメラとは関係ない（カメラの XCLK は GPIO21）。

■ センサーの基板（Pololu #3419 の製品ページより）
- VIN は 3.2〜5.5V。**信号の電圧を VIN に合わせる。**
- 通信は、既定が SPI。SPI/I2C のピンを GND につなぐと I2C になる。
- 電流は約100〜150mA。
- 配線は 8cm 以内。**首の上では守れない（実測 13cm）。** 通信が不安定なら I2C を 400kHz から 100kHz に下げる（2026-10-21。decisions.md）。

■ 確認済み（2026-10-21。ユーザーが実物で確認）
- Car Board に挿した状態で、P3 の GPIO26・27 に配線できる。

■ 未確認

- 下の「ピンの性質」の列（入力専用・ストラッピング・PSRAM）は記憶による一般的な仕様。データシートでは確かめていない。

■ 配線の計画（2026-10-21 までにユーザーが配線・首の上に仮固定した。実測は measurements.md「ToF の配線」）
- 実測：線の長さ 13cm、首の上端の高さ 12.5cm、VIN 3.3V、首を振ったときの線の張り なし。
- 出どころ：ピン番号と AMS1117 は上の回路図、VIN・SPI/I2C・線の長さは Pololu #3419 の製品ページ。
- ESP32 基板のヘッダー P3 のピンの先端に、はんだ付けで線を付ける（番号は回路図でのもの。**実物は基板の印字で確かめる**）。

| ESP32 基板（P3） | センサー（Pololu #3419） |
|---|---|
| P3-1　3V3 | VIN |
| P3-10　GPIO26 | SDA |
| P3-11　GPIO27 | SCL |
| P3-14　GND | GND |

- **VIN は 3.3V にする（5V 不可）。** Pololu の基板は信号の電圧を VIN に合わせるため、5V を入れると SDA・SCL が 5V になる。
- SPI/I2C のピンは GND につなぐ。
- 線は 8cm 以内（当初の計画）。首の上では守れず、実測 13cm。必要なら 100kHz に下げる。
- はんだ付けのあと、隣のピンと導通がないことをテスターで確かめる（**特に GPIO27 の隣の GPIO14。Nova が I2C の SCL に使用中**）。
- 単体試験で、センサーが動いているときの 3.3V の電圧の落ち方を測る（AMS1117 の余裕の確認）。

■ ソフトの事前確認（2026-10-12。確認用プロジェクト experiments/vl53l8cx_build。ビルドとコードの読み取りだけ）
- ビルド（platform・ボード・フレームワークは本体と同じ。ライブラリは無修正、警告・エラーなし）

| 環境 | ライブラリ | 結果 | Flash | RAM |
|---|---|---|---|---|
| l8cx_i2c | STM32duino VL53L8CX 2.1.0 | 成功 | 385,301 バイト（29.4%） | 24,616 バイト（7.5%） |
| l8cx_spi | 同上 | 成功 | 381,641 バイト（29.1%） | 24,696 バイト（7.5%） |
| l5cx_sparkfun | SparkFun VL53L5CX v1.0.3（比較用） | 成功 | 380,893 バイト（29.1%） | 23,176 バイト（7.1%） |

- 公式サンプルはそのままでは使えない。スケッチ側を ESP32 向けに書き換えた。
  - I2C：`Wire1.begin(26, 27, 400000)`。LPn・PWREN はつながない（-1）。公式の `A3`・`11` は Nucleo のピン。
  - SPI：公式の `SPIClass(MOSI, MISO, CLK)` は STM32 だけの書き方。`SPIClass(VSPI)` と `begin(SCK, MISO, MOSI, CS)` にした。
- ファームウェアの転送（起動時の `init()`）
  - 大きさは 0x15000＝86,016 バイト。3回（32KB・32KB・20KB）に分けて書く。
  - I2C では、1回の通信が「レジスタ 2バイト＋データ 32バイト＝34バイト」。ESP32 では `BUFFER_LENGTH` が定義されていないので、
    ライブラリの既定の 32 が使われる。通信は約2,688回。
  - Nova の環境の Wire の送信バッファは 128バイト（Wire.h の `I2C_BUFFER_LENGTH`）。**超えない。**
  - かかる時間は、400kHz で約2〜3秒、1MHz で約1秒（計算による見積もり。実測ではない）。
  - ビルドフラグ `-DDEFAULT_I2C_BUFFER_LEN=126` で1回を 128バイトにでき、通信は約680回に減るはず（ソースを読んだ限り。未ビルド・未確認）。
- Flash と RAM
  - ファームウェアの配列は Flash に置かれる（アドレス 0x3F400DA8、大きさ 0x15000。nm で確認）。RAM にはコピーされない。
  - RAM を使うのは、センサーのオブジェクト 2,788 バイト。
- アドレスとクロック
  - アドレスは 8ビットの書き方（0x52）で持ち、通信のたびにライブラリが 1ビットずらして 0x29 にする。`begin()` に渡すときも 0x52 の形。
  - クロックはライブラリでは設定しない。`Wire1.begin(SDA, SCL, 周波数)` か `Wire1.setClock()` で決める。
- **センサーが応答しないと、永久に止まる**（元の vl53l8cx.h の `IO_Read`。**2026-10-24 に直した**。下の「ライブラリの取り込みと修正」）
  - 送信が成功するまでくり返すループ（119〜135行）と、読めるまでくり返すループ（138〜147行）に、回数の上限がない。
  - 配線が外れると Nova の loop が止まり、安全層も動かなくなる。
- `IO_Write` は、途中の送信の結果を見ていない（最後の1回だけ返す）。転送の失敗は、そのあとの確認で分かる。
- SPI 版（使わない。参考）：1回の読み書きで 4,098 バイトの配列をスタックに置く（loop のスタックは 8,192 バイト）。
  転送は 4,096 バイトずつ・21回。

■ ライブラリの取り込みと修正（2026-10-24。コードの読み取りとビルドだけ。実機では未確認）
- lib/STM32duino_VL53L8CX に 2.1.0（タグ 2.1.0＝a93a9d6）を取り込み、`IO_Read` を直した（NOVA_PATCH.md・THIRD_PARTY_NOTICES.md）。
  - 送信のくり返しは `NOVA_IO_READ_TX_TRIES`（3回）まで。`requestFrom` で読めたバイト数が要求より少なければ、すぐに 1 を返す（32バイトずつ読む分岐・1回で読む分岐の両方）。
- 本体（src/）からはまだ使わない。本体のビルドは Flash 411,645 バイト・RAM 54,328 バイトで、取り込みの前と同じ（lib/ にあっても include しなければリンクされない）。
- **Arduino-ESP32 2.0.17 では `endTransmission(false)` は送らずに 0 を返す**（Wire.cpp の `endTransmission`。送るのは次の `requestFrom` で、書いて読むのを1回の通信で行う）。
  したがって ESP32 で永久に止まるのは、読み出しのループ（138〜147行）のほうだった。送信のループの上限は、他の環境向けの保険。
- **Wire の1回のタイムアウトの既定は 50ms**（framework-arduinoespressif32 4.20017＝Arduino-ESP32 2.0.17 の Wire.cpp：`_timeOutMillis(50)`。
  Wire.h のコメントも「default timeout of i2c transactions is 50ms」）。`Wire1.setTimeOut()` で変えられる。
  本体の Wire（GPIO13・14）は、スプリント3.5 で 5ms にしてある。
  - センサーがない（アドレスに NACK）ときは、タイムアウトを待たずにすぐ失敗する（見立て。実機では未確認）。
  - バスが張りついた（SDA が Low のまま）ときは、1回の通信ごとに最大 50ms 待つ。
- **エラーが戻り値まで伝わるか**（コードの読み取り）
  - `begin()`：**I2C の通信をしない**（LPn・I2C_RST のピンの設定と、アドレスを覚えるだけ）。**いつも 0 を返す**。センサーがあるかは分からない。
  - `init()`：読み書きの結果を全部 `|=` でためて返す。**伝わる。** 起動の確認（267行）とMCUの起動の確認（340行）で失敗していれば、そこで抜ける。
    - ただし、待ちのループ（`_vl53l8cx_poll_for_answer`）は読み出しが失敗しても抜けず、200回（10ms の待ち×200＝約2秒）まで回ってから戻る。
      センサーがないと、`init()` は約2秒＋α で 0 以外を返す見込み（ACK がないので、1回の通信はすぐ失敗する前提）。
    - バスが張りついたときは、待ちのループ1回あたり約 60ms（50ms＋10ms）×200＝**約12秒**かかる見込み。
    - 途中（MCUの起動の確認のあと）でセンサーが応答しなくなると、待ちのループが最大6回あるので、約2秒×6＝**約12秒**かかりうる（バスが張りついていれば、さらに長い）。
    - `IO_Write` は途中の送信の結果を見ていない（最後の1回だけ返す。上の「ソフトの事前確認」）。途中だけの失敗は、そのあとの読み出しやチェックサムで分かる。
  - `get_ranging_data()`：読み出しの結果を `|=` でためて返す。**伝わる。** **ただし、読み出しに失敗しても、そのあとバッファの解析を続ける。**
    バッファには前の内容が残っており（失敗したのが途中のかたまりなら、前半だけ新しい）、それを並べ替えてブロックの見出しとして読む。
    見出しの大きさ（最大 12×4,095 バイト）で `memcpy` するので、**結果の構造体の外を書きつぶすおそれがある**（見立て。
    元は永久ループで止まっていたので、この経路には来なかった）。→ **2026-10-24 に直した**（失敗したら解析しないで戻る）。
  - `check_data_ready()`：読み出しの結果を返す（伝わる）。元は失敗しても残ったバッファで `*p_isReady` を決めていた。→ 2026-10-24 に直した（失敗なら 0）。
  - `start_ranging()`：元は解像度の読み出しに失敗しても、残った値（最大 255）で読み出しの大きさを決めていた。
    あとの `get_ranging_data()` で一時バッファ（解像度 64 用）の外まで読み込むおそれ。→ 2026-10-24 に直した（そこで戻る）。
  - 同じ形（読み出しの失敗を見ずに解析を続ける）のうち、直していないもの（読む大きさが固定で、構造体の外は書かない。エラーは戻り値に伝わる）：
    - `vl53l8cx_dci_read_data`：失敗しても、残ったバッファを並べ替えて `data` に写す。これを使う `get_*` は古い値を返し、
      `set_*`（`set_resolution`・`set_ranging_mode`・`set_external_sync_pin_enable`、`dci_replace_data` を使う `set_ranging_frequency_hz`・
      `set_integration_time_ms`・`set_sharpener_percent`・`set_target_order`・`set_VHV_repeat_count`、検出しきい値のプラグイン）は、古い内容をセンサーに書き戻す。
    - `init()`：チェックサムと NVM（オフセット）の読み出しの失敗後も、残った内容で比べる・センサーへ送る。`_vl53l8cx_poll_for_mcu_boot` は失敗すると初期化していない変数で判定する。
    - `is_alive()`・`get_power_mode()`・`set_power_mode()`：失敗すると初期化していない変数で判定する（`is_alive` の alive はほぼ 0 になるが保証はない。戻り値を先に見る）。
    - `stop_ranging()`：失敗しても MCU を止める手順を続け、待ちのループ（10ms×500）で約5秒止まりうる。
    - xtalk のプラグイン（`calibrate_xtalk`・`get_caldata_xtalk`）：失敗しても残った内容を写す（固定の大きさ）。
  - `begin()`・`is_alive()` は単体試験 `l8cx_init_time` で戻り値と時間を出す（is_alive が 0 でも init は呼ぶ）。

■ 組み込みの前の条件
- ~~`IO_Read` の永久ループ2か所に、回数の上限を付ける~~ → 2026-10-24 に済んだ（上）。
- ~~`get_ranging_data()` が読み出しに失敗したあとの解析の扱いを決める~~ → 2026-10-24 に直した（上。`start_ranging`・`check_data_ready` も）。
- **本体に組み込むときの注意（使い方の決まり。2026-10-24。decisions.md）**：上の「直していないもの」はライブラリを直さず、使い方で避ける。
  - 起動時の `init()` と設定（`set_*`）で1つでも失敗したら、その起動中は ToF を使わない（超音波だけで動く）。
  - 走行中に呼ぶのは `check_data_ready` と `get_ranging_data` だけ。
  - `stop_ranging()` は走行中に呼ばない。
  - `is_alive()`・`get_power_mode()`・`set_power_mode()` は、戻り値を先に見る。
  - `start_ranging` が失敗したら `get_ranging_data` を呼ばない（`data_read_size` が 0 のままだと、フッターの位置の計算が負になる）。
- `begin()` ではセンサーの有無が分からない。起動時に確かめるなら `is_alive()`（読み書き4回）を `init()` の前に呼ぶ。
- **初期化（約2〜3秒、見積もり）は起動時だけ。走行中にやり直さない。**
- 失敗は捨てずに数え、`t` に出す（ジャイロと同じ）。センサーが使えないときは、超音波だけで今までどおり動く。

■ 実機で測ること（センサーが届いてから）
- 初期化にかかる時間。
- `get_ranging_data` が loop を止める時間（4×4 と 8×8）。
- 浅い角度の壁（10・20・30・45°）の見え方。
- 床が見え始める段（何段目から床が写るか。取り付けの高さと向きで変わる）。
- センサーが動いているときの 3.3V の電圧の落ち方（上の「配線の計画」）。
