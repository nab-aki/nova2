# ID 15：障害物で困る（最小版 v1）

カタログ：分類C／難易度 中／依存 9／位置づけ 2／実装順 2

前が塞がれたときに、後退して向きを変え、通れる方向を見つける。
v1 は「立て直す」ことだけを扱い、首かしげと「？」の目（v2）は入れない。

## きっかけ

ID9「気づく」で障害物に気づいて止まり、気づいた瞬間の反応
（目を見開く・停止後の距離を出す）が終わってもまだ正面が塞がっているとき。

- ID9 の反応中（`NOTICE_WIDE_MS` 1200ms と `NOTICE_STOP_REPORT_MS` 800ms の長いほう）は待つ。
  設計原則1「気づく（目）→ 向く（首）→ 動く（車体）」の順を守るため。
- いちど始めたら、正面が空くか、あきらめるまで続ける（途中で ID25 に戻さない）。

## 動作の流れ

```
[少し後退] → [左を測る] → [右を測る] → [空いているほうを決める]
                                              ↓
        ┌──────────────────────────→ [少し回る] → [止めて正面を測る]
        │（まだ塞がっている。最大12回）              ↓
        └─────────────────────────────────┘
                                   （空いた）→ 終了（ID25 に戻る）
                            （12回まわってもだめ）→ [休む] → 最初へ
```

1. **少し後退**：`TROUBLE_BACK_SPEED`（-0.0385＝巡航と同じ速さ）で
   `TROUBLE_BACK_MS`（500ms）下がる。`TROUBLE_BACK_RAMP_MS`（300ms）かけて加速し、急に下がらない。
   - 後退の前後で正面の距離を記録し、**どれだけ下がれたか**をシリアルに出す
     （実測が取れるので、後退の時間を詰める材料にする）。
   - 後方にはセンサーがない。短く下がるだけにして、当たったら止まれないことを
     v1 の限界として受け入れる（下記「既知の限界」）。
2. **左右を測る**：首の使用権を「測距」で取り、左 → 右 の順に測る。
   角度・回数・値の採り方は ID25 の見回しと同じ（±`WANDER_SCAN_PAN_DEG` 50°、3回、最も近い値）。
   正面は測らない（塞がっているのは分かっているため）。
3. **決める**：測った値が**遠いほう**を選ぶ。
   - 差が `TROUBLE_SIDE_DIFF_CM`（10cm）未満で甲乙つけがたいときは、
     前回と反対側を選ぶ（毎回同じ側に回って、同じところを往復しないため）。
4. **少し回る**：選んだ側へ**その場回転**（壁の前なので片側旋回は使わない）。
   1回の回転は `TROUBLE_TURN_STEP_MS`（初期500ms。うちキック `MOTOR_ROTATE_KICK_MS` 300ms・保持200ms）。実機では1ステップで約6°しか回らなかったので、デバッグの調整キーで値を探している（25_wander.md）。
5. **止めて正面を測る**：回転を止め、`TROUBLE_CHECK_SETTLE_MS`（200ms）待ってから
   `Obstacle_Reset()` を呼び、履歴が5回たまる（`Obstacle_IsReady`）まで待って判定する
   （下記「空いたの基準」）。
   - 回転で見る方向が変わるので、回転中・車体が揺れている間の測距は捨てる。
   - 空いた → **終了**。ID25 に戻り、見回しから歩き出す。
   - まだ塞がっている → 4 に戻る（同じ側へ回り続ける）。
6. **あきらめて休む**：4〜5 を `TROUBLE_MAX_STEPS`（12回）繰り返しても空かなければ、
   `TROUBLE_GIVEUP_REST_MS`（5000ms）休んでから 1 に戻る（もう一度後退からやり直す）。
   - 回転の角度は測れないので、12回で「だいたい一周」とみなす。**回る角度は未測定**。
     実機で1ステップの角度を測り、`TROUBLE_MAX_STEPS` を詰める。
   - 休んでいる間は止まったまま。まばたきは続く（目レイヤーは別なので自然に続く）。

## 「空いた」の基準と、履歴をリセットしたときの状態

回転のたびに `Obstacle_Reset()` を呼ぶので、そのときに何が消えて何が残るかを決めておく。

### `Obstacle_Reset()` で何が変わるか（src/core/obstacle.cpp。既存の動作）

| 中身 | リセットで | 理由 |
|---|---|---|
| 測距の履歴（最大5回） | **捨てる** | 回転前の方向を見た値なので使えない |
| `Obstacle_IsReady()` | **false に戻る**（5回たまるまで） | たまるまでは判定を変えない |
| 「あり／なし」（`Obstacle_IsBlocked`） | **そのまま残る**。リセットでは変わらない | 履歴がたまり直すまで、いまの判定を保つ（安全側） |
| 非常停止（`Obstacle_IsEmergency`） | false に戻る | 1回の測距で決まる値なので、履歴と一緒に捨てる |

したがって、回転のあとは**「あり」が残ったまま**、新しい5回で判定し直される。
共通部品側のヒステリシスでは、「あり」から「なし」に戻るには
直近5回のうち3回が `OBSTACLE_STOP_CM + OBSTACLE_CLEAR_MARGIN_CM`（36＋10＝**46cm**）以上必要。

### ID15 の再判定が使う閾値

ID15 は、**自分の基準 `TROUBLE_CLEAR_CM`（46cm）と、共通部品の「なし」の両方**がそろったときだけ
「空いた」とする。どちらも、リセット後にたまった同じ5回の測距から見る。

| 見るもの | 条件 |
|---|---|
| ID15 の基準 | その5回のうち**最も近い有効値** ≥ `TROUBLE_CLEAR_CM`（46cm）。有効値が1つもなければ空いている扱い |
| 共通部品の判定 | `Obstacle_IsReady()` が true で、`Obstacle_IsBlocked()` が false（5回中3回が46cm以上） |

- ID15 の基準のほうが厳しい（5回すべてが46cm以上でないと通らない）。
  壁の端をかすめただけで「空いた」と判断して歩き出さないため。
- 共通部品の判定も見るのは、**引き継ぎのため**。ID15 が終わって ID25 に戻った瞬間に
  共通部品がまだ「あり」だと、安全層が前進を止め、ID9 がもう一度発動してしまう
  （気づいた回数も余分に数えてしまう）。両方そろってから戻す。
- `TROUBLE_CLEAR_CM` の初期値 46cm は、共通部品の「なし」の閾値（36＋10）と**わざと同じ**にしている。
  ここだけ下げると、ID15 は空いたと思っても共通部品は「あり」のままになり、
  上の理由でいつまでも戻れなくなる。下げるときは `OBSTACLE_STOP_CM` か
  `OBSTACLE_CLEAR_MARGIN_CM` も一緒に見直すこと。

## 持ち上げられたとき

[25_wander.md](25_wander.md) の「共通部品への変更」のとおり、持ち上げ（ライン111）を
検知したら安全層が動きを止める（目標速度も回転も0に戻す）。

ID15 は、持ち上げられている間は状態を進めず、床に戻されたら**最初（後退）からやり直す**。
持ち上げている間に向きも場所も変わっているので、左右の測距値も
「あと何回回れば一周か」（`TROUBLE_MAX_STEPS` までの回数）も引き継がない。

## 首の使い方

- 2（左右を測る）の間だけ、首の使用権を「測距」（優先度20）で取る。
- 車体が動いている間（後退・回転）は、安全層が「安全」（優先度30）で首を正面・水平に固定する。
  したがって回転中に首が動くことはなく、回転後の正面の測距は首が正面のまま行われる。
- 2 が終わったら使用権を返す。

## 安全層との関係（[25_wander.md](25_wander.md) の共通部品への変更を前提にする）

この振る舞いは「正面に障害物がある」状態で動くため、安全層が
すべての動きを止めてしまうと成立しない。安全層を次のように変える。

- 障害物があるとき止めるのは**前進と片側旋回だけ**。後退とその場回転は止めない。
- 持ち上げ（ライン111）のときは、後退も回転も含めてすべて止める。

非常停止距離（`OBSTACLE_EMERGENCY_CM` 12cm）も同じ扱いにする。
12cm まで近いときこそ、後退とその場回転で離れる必要があるため。

## 優先度

| レイヤー | 振る舞い | 優先度 | 発動する条件 |
|---|---|---|---|
| 車体 | **障害物で困る（ID15）** | **40** | ID9 の反応が終わってもまだ塞がっている。始めたら終わるまで続く |
| 車体 | 気づく（ID9） | 30 | 障害物がある、または気づいた直後の反応中 |
| 車体 | うろうろ（ID25） | 20 | 常に |

ID9 より高くするのは、立て直しの最中に ID9 に主導権を戻さないため。
ID9 は「気づいた瞬間」だけを受け持ち、そのあとの行動は ID15 が引き継ぐ。

## 調整パラメータ（config.h）

| 名前 | 初期値 | 意味 |
|---|---|---|
| TROUBLE_BACK_SPEED | -0.0385 | 後退の速度（正規化速度。巡航と同じ速さで逆向き） |
| TROUBLE_BACK_MS | 500 | 後退する時間 |
| TROUBLE_BACK_RAMP_MS | 300 | 後退の加速にかける時間 |
| TROUBLE_SIDE_DIFF_CM | 10.0 | 左右の差がこれ未満なら「甲乙つけがたい」 |
| TROUBLE_CLEAR_CM | 46.0 | 正面が「空いた」と認める距離（上記。共通部品の 36＋10 と同じ値にしてある） |
| TROUBLE_TURN_STEP_MS | 500 | 1回に回る時間（うちキック `MOTOR_ROTATE_KICK_MS` 300ms） |
| TROUBLE_CHECK_SETTLE_MS | 200 | 回転を止めてから測り直すまでの待ち（車体の揺れが収まるまで） |
| TROUBLE_MAX_STEPS | 12 | 「一周した」とみなす回転の回数 |
| TROUBLE_GIVEUP_REST_MS | 5000 | 一周しても空かないときに休む時間 |
| PRIORITY_TROUBLE | 40 | 車体レイヤーの優先度 |

## 初期値の根拠

- **後退の速度**：後退の最低PWMは実測 575（＋余裕で650）。
  いまの換算は正負とも `MOTOR_PWM_MIN`（675）を下限にするので、
  -0.0385 は PWM -726 となり、650 を上回っていて確実に動く。
  巡航と同じ速さなら、実測の 41.1cm/s から 500ms で**およそ15cm**下がる計算
  （加速300msぶんを引くとおよそ10cm）。実機で測って詰める。
- **後退 500ms**：ID9 が止まる位置は壁から約21cm。10〜15cm 下がれば 31〜36cm になり、
  その場回転しても角が壁に当たりにくい。長く下がると後ろの物に当たる危険が増える。
- **左右の差 10cm**：静止時のばらつきは σ0.2cm 以下なので、10cm の差は確実に意味がある。
  これ未満のときに前回と反対を選ぶのは、行き止まりで同じ動きを繰り返さないため。
- **1回の回転 500ms**：キック300ms を含む最小限の長さ。細かく刻んで測り直すほうが、
  行き過ぎて別の壁を向くより確実。ただし遅いので、実機を見て詰める。
- **12回で一周**：1ステップ30°の仮定。**未測定**なので実機で確認する。
- **休む 5秒**：あきらめたことが見た目に分かる長さ。
  そのあと後退からやり直すので、休んでいる間に状況が変わらなくても抜けられることがある。

## 完了条件

- 動作：壁の前で止まったあと、**後退 → 左右確認 → 回転 → 再判定** が一通り動き、
  空いている方向を向いて歩き出す。狭い部屋の5分間の試験（ID25）で、
  塞がれるたびに立て直せる（動けなくなった回数を記録する）。
- 動作：部屋の角（2面が近い）で試し、抜けられるか・あきらめて休むかを記録する。
- 愛らしさの観点：後退と回転が唐突でないか。困っている様子に見えるか
  （v2 で首かしげと「？」の目を足す前提なので、v1 は動きだけで見る）。

## 既知の限界（v1）

- **後方にセンサーがない。** 後退中に後ろの物に当たっても止まれない。
  後退を 500ms と短くして影響を小さくするだけにとどめる。
- **回転した角度が分からない。** 時間で刻んでいるので、電池の減りや床で回る量が変わる。
  「一周」は 12回という仮の数で判断している。
- **狭い場所では空きが見つからないことがある。** 正面が「空いた」と認めるには
  `TROUBLE_CLEAR_CM`（46cm）以上が必要。
  四方が 40cm 程度の狭い場所では、一周しても空かず、休む→やり直すを繰り返す。
  5分間の試験でこれが起きたら、閾値かこの立て直しの手順を見直す。
- **浅い角度の壁は、左右を測っても見つからないことがある。** 首を50°振っても
  入射角が浅いままなら超音波は戻らず、「空いている」と読める。ID26「詰まり脱出」で扱う。
