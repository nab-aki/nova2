# 共通部品：障害物の判定と安全層（v1）

ID には紐づかない共通部品（#0）。ID9・ID15・ID25・ID26 が共通で使う。

## 目的

測距値は1回きりでは信用しない。複数回の結果で「障害物あり／なし」を決め、
あるときは、なめらか加減速を通さずに即停止する。

## 障害物の判定（src/core/obstacle.*）

### 1回の測距の分類

首が安定している（`Neck_IsSteady`）ときに完了した測距だけを使い、次のように分類する。

| 測距の結果 | 分類 | 理由 |
|---|---|---|
| 有効（2〜80cm）で 閾値未満 | 近い | 障害物 |
| 有効（2〜80cm）で 閾値以上 | 遠い | 空いている |
| 2cm未満 | 近い | 近すぎて測れない。危険側に倒す |
| 80cmより遠い | 遠い | 実測の安定範囲外。空いているとみなす |
| エコーなし | 遠い | 正面に何もない |

「エコーなし＝遠い」とするのは、部屋の中央など何もない方向でも前進できるようにするため。
ただしセンサーの故障・断線も「遠い」と読めてしまうので、エコーなしが
`ULTRASONIC_NO_ECHO_WARN_MS`（10秒）続いたらシリアルに警告を1行出す（動作は変えない）。

### 接近速度

履歴の中の有効な測距値から、最も古いものと最も新しいものを使って求める。

接近速度（cm/s） ＝ (古い距離 − 新しい距離) × 1000 ÷ 時間差(ms)

正なら近づいている。時間差が `OBSTACLE_SPEED_MIN_MS`（150ms）未満のときは求めない。
この値で巡航速度を実測し、停止閾値・巡航速度を見直す（2026-09-21 に実施。下記）。

### 判定

- 直近 `OBSTACLE_HISTORY`（5）回のうち、`OBSTACLE_NEAR_COUNT`（3）回以上が「近い」なら **障害物あり**。
- いちど「あり」になったら、直近5回のうち3回以上が
  `OBSTACLE_STOP_CM + OBSTACLE_CLEAR_MARGIN_CM`（36＋10＝46cm）以上になるまで「あり」のまま
  （ヒステリシス。壁ぎわで進む・止まるを繰り返さないため）。
- 首が動き始めたら履歴を捨てる。捨てた直後は、5回たまるまで判定を変えない。

### なぜ「5回のうち3回」か

実測（docs/measurements.md）では、静止時のばらつきは σ 0.21cm 以下・有効20/20 と非常に安定しており、
ノイズ対策としては1回でも足りる。この多数決は、次のような一時的な異常を弾くためのもの。

- 走行中の振動や床の段差で、一瞬だけ違う物を見てしまう
- 斜めの面での反射が抜ける／戻ってくる

## 安全層（src/core/safety.*）

`Arbiter_Update` の後、`Motion_Update` の前に毎ループ呼び、振る舞いの指示を上書きする。

1. **車体が動いている間は首を正面・水平に固定する**
   動いている間（回転・旋回を含む）、安全（優先度30）で首の使用権を取り、正面・水平を申し出続ける。
   止まったら使用権を返す（停止中は測距・表情が首を使える）。
2. **持ち上げられたら、すべての動きを即座に止める**（スプリント2で追加）
3. **障害物あり、または非常停止距離未満なら、前進と片側旋回を即停止**
   `Motion_EmergencyStop()` を呼ぶ。なめらか加減速（Smoother）を通さず、その場でPWMを0にする。
   非常停止距離（12cm）は多数決を待たず、1回の測距で発動する。

急停止をしない（設計原則3）は通常の走行に対する原則で、障害物を見つけたときは例外とする。

### 持ち上げの検知（スプリント2で追加）

ライントラッキングが `SAFETY_LIFT_TRACK`（`111`）になったら持ち上げとみなす
（実測：床では `000`、持ち上げると `111`。docs/measurements.md）。

- 止めるのは1回読んだ時点で即座に。`Motion_EmergencyStop()` で目標速度・現在速度を0にし、
  回転中なら回転も取り消す。
- 解除は慎重に。`111` 以外が `SAFETY_LIFT_CLEAR_COUNT`（3回）続けて**読めた**ときだけ。
  ライントラッキングは `TRACK_READ_INTERVAL_MS`（100ms）ごとにしか読まないので、
  数えるのは読み取り回数（約300ms に相当する）。毎ループ数えると数msで解除されてしまう。
- 持ち上げられている間、振る舞いは状態を進めない。床に戻ったら続きからではなく、
  ID25 は「ため」から、ID15 は最初からやり直す（docs/specs/25_wander.md）。

### 障害物のときに止める動き（スプリント2で変更）

障害物があるときに止めるのは、**障害物へ近づく向きの動きだけ**にする。
すべて止めると、ID15「障害物で困る」が壁の前で立て直せない（後退も回転もできない）ため。

| 動き | 障害物があるとき | 理由 |
|---|---|---|
| 前進 | **止める** | 障害物に近づく |
| 片側旋回 | **止める** | 片輪が前に出るので、車体が前へふくらむ |
| 後退 | 止めない | 障害物から離れる |
| その場回転 | 止めない | 中心が動かないので、角が壁に当たらない |

非常停止距離（12cm）でも同じ扱いにする。そこまで近いときこそ、後退とその場回転で離れる必要があるため。
持ち上げの停止は、向きに関わらずすべての動きを止める。

## 回転（その場回転・片側旋回。スプリント2で追加）

モーターに書き込む場所を1つに保つため、回転も `src/core/motion.*` が持つ
（`Motion_StartTurn` / `Motion_StopTurn` / `Motion_IsTurning`）。
実測（docs/measurements.md）のとおり動き出しに大きなPWMが要るので、
キック（`MOTOR_TURN_KICK_MS`）→ 保持 の2段階で出す。生のPWMなので `Motor_DrivePwm()` を使う。
回転の開始時と終了時に `Obstacle_Reset()` を呼ぶ（回っている間は別の方向を見ているため）。

詳しくは [25_wander.md](25_wander.md) の「回転」を参照。

## 調整パラメータ（config.h）

| 名前 | 初期値 | 意味 |
|---|---|---|
| OBSTACLE_HISTORY | 5 | 判定に使う直近の測距回数 |
| OBSTACLE_NEAR_COUNT | 3 | このうち何回が閾値未満なら「あり」か |
| OBSTACLE_STOP_CM | 36.0 | 停止閾値（35.0 から変更） |
| OBSTACLE_CLEAR_MARGIN_CM | 10.0 | ヒステリシス。46cm 以上に戻ったら「なくなった」 |
| OBSTACLE_EMERGENCY_CM | 12.0 | 1回でもこれ未満なら即停止 |
| OBSTACLE_SPEED_MIN_MS | 150 | 接近速度を求めるのに必要な最小の時間差 |
| ULTRASONIC_NO_ECHO_WARN_MS | 10000 | エコーなしがこれだけ続いたら警告を1行出す |
| CRUISE_SPEED | 0.0385 | 巡航の正規化速度（PWM 726 相当。0.23→0.02→0.0385。MOTOR_PWM_MIN 675 でも PWM726 になるよう計算し直した） |
| ULTRASONIC_INTERVAL_MS | 60 | 測距の間隔（100 から変更） |
| MOTOR_PWM_MIN | 675 | 前進の最低PWM。実測の動き出し 600 に電池低下の余裕を足した値（1300→700→675。docs/measurements.md） |
| SAFETY_LIFT_TRACK | 0x07 | 持ち上げと判定するライントラッキングの値（111） |
| SAFETY_LIFT_CLEAR_COUNT | 3 | 床に戻ったと認めるまでの連続読み取り回数（約300ms） |
| MOTOR_TURN_KICK_MS | 300 | 回転のキック（動き出し）を出す時間（**未測定の仮値**） |

## 初期値の根拠

### 測距の間隔を 100ms → 60ms にする

- 実測：60ms間隔×20回で、全対象・全距離で有効20/20。60ms は十分に間に合う。
- 停止距離の測定は 30ms 間隔で動いていた。
- 「5回のうち3回」で判定するため、検知には最悪3回分かかる。
  100ms なら 300ms、60ms なら 180ms。速いほうが停止距離が縮む。

### 最低PWM を 1300 → 700 にする

- config.h の 1300 は tools/pwm_test の **1000Hz** での実測値。本体は 50Hz。
- 停止距離の測定（50Hz）では PWM 700 でも前進した（走行2398ms、滑走6.3cm）。
  700未満は未測定。
- 1300 のままだと `Motor_SpeedToPwm` の下限が 1300 になり、狙いの PWM 1000 を出せない。
- 副次的な利点：走り出しの最小PWMが下がるので、発進がなだらかになる。

### 巡航PWM 1000 と 停止閾値 35cm（当初。2026-09-21 に見直し）

実測（閾値30cm・即停止・フローリング・電池7.70V）：

| PWM | 滑走 | 停止後の距離 |
|---|---|---|
| 1300 | 17.0cm | 10.4cm |
| 1100 | 15.4cm | 13.0cm |
| **1000** | **13.0cm** | **15.2cm** |
| 900 | 11.8cm | 17.4cm |

- 巡航は PWM 1000 を選ぶ。滑走13.0cm と十分短く、部屋をうろうろする速さとして妥当。
- 測定ツールは 30ms 間隔・1回の測距で即停止していた。Nova は 60ms 間隔・3回の多数決なので、
  検知が最悪 150ms 遅れる（180ms − 30ms）。
- 巡航速度は未測定。停止距離測定の走行時間（PWM1000 で1708ms）と、
  ツールの案内どおり約80cm から走らせたという前提から、**およそ35cm/s と推定**。
  150ms の遅れは約5cm に相当する。
- したがって停止閾値は、実測の閾値30cmに5cm足して **35cm** とする。
  予想される停止後の距離：35 − 13.0（滑走）− 5（判定の遅れ）≒ **17cm**。
- 非常停止距離 12cm は、この17cmより下、最小検出距離2cmより十分上に置いた最後の備え。

巡航速度は推定値なので、実機で停止後の距離を確認して調整する。

### 巡航PWM 726 と 停止閾値 36cm（2026-09-21 の見直し）

ID9 の実機評価（[09_notice.md](09_notice.md)）で、上の推定が外れていることが分かった。

| 項目 | 実測 | 当初の予想 |
|---|---|---|
| 接近速度 | 59.6cm/s | 約35cm/s |
| 気づいた距離 | 25.3cm | 閾値 35cm |
| 停止後の距離 | 約10cm | 約17cm |

- 推定が約1.7倍外れた原因は「約80cm から走らせた」という仮定。59.6cm/s から逆算すると
  走行距離は約87cm で、実際のスタートは約115cm だった。モーターのモデルは正しい。
- 速度モデルを立て直した。停止距離測定の走行時間（加速500msぶんを補正して D = v×(T−0.25s)）から
  求めた相対速度は、PWM700〜1300 で PWM に正比例（原点を通る直線）する。実測 59.6cm/s＠PWM999 を
  当てて **v ≒ 0.0597 × PWM**。滑走は表の 700/1000 比 6.3/13.0 = 0.485 ≒ (0.7)^2 で
  **滑走 ∝ v^2**。
- 巡航は **CRUISE_SPEED 0.02（PWM726・推定43.3cm/s）** に下げる。ねらいは 35〜40cm/s だったが、
  40cm/s は PWM670・35cm/s は PWM586 で、どちらも `MOTOR_PWM_MIN` 700（未測定域）より下。
  0.02 が今の構成で出せる最も遅い巡航。
- 停止閾値は **36cm**。20 +（43.3×0.180 = 7.8、判定の遅れ）+（15.3×(726/999)^2 = 8.1、滑走）≒ 36。
  巡航を下げずに 20cm を取るには 46cm 必要だった。
- 判定の遅れ 9.7cm（163ms 相当）は多数決そのもの。1回目の「近い」まで最大60ms、2回目・3回目で
  +120ms なので 120〜180ms。測距の完了から停止までに余分な遅れはない（同じ loop 内で判定し、
  安全層が `Motor_Stop` を直接呼ぶ。`Motion_Update` の20ms待ちは通らない）。
- **未了**：PWM450〜700 が未測定のため 35cm/s に届いていない。また PWM が最低値ぎわなので、
  加速の「ため」（ID7）と速度の揺らぎが効かない。最低PWMの再測定を先に済ませたい。

## 既知の限界（実測から）

- **斜め45°の壁は、近いときに遠く出る。** 実測では想定10cm で 36.2cm、想定30cm で 48.7cm。
  ばらつきは小さく（σ0.2以下）、20/20回とも遠く出るので、多数決でも非常停止でも防げない。
  v1 では対処しない。完了条件の確認は正対した壁で行う。
  斜めの面への対処は ID15「障害物で困る」・ID25「うろうろ」とあわせてスプリント2以降で扱う。
- **30°より浅い角度の壁（壁と平行に近い面）は検知できず、衝突する。** 2026-09-21 の ID9 実機評価
  （床・1mスタート）で確認した。正対（0°）と30°では止まれるが、それより浅くなると超音波が
  斜めに反射して戻らないため、そもそも距離が取れない。停止閾値・多数決・測距間隔・巡航速度を
  どう動かしても対処できない（測れていないものは判定できない）。
  ID25「うろうろ」の事前の左右確認（歩き出す前に首で左右を見て、横の壁が近ければその方向を避ける）と
  ID26「詰まり脱出」で扱う（docs/decisions.md 2026-09-21）。
- **走行中の電池電圧の読み取りが乱れることがある。** 実測で 4.46〜6.76V の異常値が出た回がある。
  電池電圧を走行の判断に使うのは避ける（ID22 で扱うときに再確認する）。
