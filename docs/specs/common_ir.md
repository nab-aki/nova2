# 共通部品：IR受信（リモコン）（v1）

ID には紐づかない共通部品（#0）。リモコンでの一時停止・再開（#0）と、ID20「呼びかけ」が使う。

## 目的

付属のIRリモコンのボタンを、ケーブルなし（PCなし）でも受け取れるようにする。
`src/hal/hal_ir.*` は、押されたボタンのコードを返すだけにして、割り当ては使う側が決める。

## 方式（IRremoteESP8266 を使う）

| 項目 | 公式の Freenove_IR_Lib（v1.0.1） | IRremoteESP8266（v2.8.6） |
|---|---|---|
| ビルド | **できない**：`driver/rmt_rx.h`（新しい RMT ドライバ）が Arduino-ESP32 2.0.17 にない（実際に fatal error） | **できる**：改変なし（NEC のみ有効でフラッシュ +約12.5KB、RAM +約100バイト。こちらのコードに警告なし） |
| 受信の仕組み | RMT の受信（`rmtRead` で待つ。公式サンプルは別タスクで回す） | GPIO の変化割り込みと、フレームの終わりを見る単発のハードウェアタイマー（3番）。`decode()` は待たない |
| 他の部品との取り合い | WS2812 も RMT を使う。2.x の RMT の受信は別のAPI（コールバック）で、同時利用は未確認 | 超音波は GPIO 割り込み（別のピン）、WS2812 は RMT、ブザーは LEDC、PCA9685 は I2C。ハードウェアタイマーを使う部品は他にない |
| 改変の量 | 2.x 向けに RMT の受信をコールバック方式に書き換える（ライブラリ2ファイルの数十行）。公式の `task()` は待つ作りなので、待たない形にも直す | なし（`hal_ir.*` の約80行だけ） |
| 動かなかったときのリスク | 高い：2.x の RMT 受信の挙動を、こちらで改変して確かめることになる | 低い：ESP32 の 2.x で広く使われている |

どちらも、GPIO0 で実際に受信できるかは実機で確かめるまで分からない。
IRremoteESP8266 で動かなければ、GPIO 割り込みで NEC を読む自作の受信に切り替える。

決定（docs/decisions.md 2026-09-21）：**IRremoteESP8266 を使う**。
platformio のライブラリ管理で取得する（`lib_deps`、バージョン固定。`.pio/libdeps/` は Git に入れない）。
プロトコルは NEC だけを有効にする（`-D_IR_ENABLE_DEFAULT_=false -DDECODE_NEC=true`）。

## ピン

公式サンプル 05.1〜05.3 の `RECV_PIN` と同じ **GPIO0**（`PIN_IR_RECV`）。
GPIO0 は起動時のモード選択（strapping）のピン。受信モジュールは待機時に High なので通常は問題ないが、
起動の瞬間にリモコンを押すと起動を妨げるおそれがある。カメラのクロックと共用だが、カメラは未使用。

## API（src/hal/hal_ir.h）

```
void Ir_Setup(void);
bool Ir_Poll(uint32_t *code);              // 新しく押されたボタンがあれば true
const char *Ir_ButtonName(uint32_t code);  // ボタン名。未登録は NULL
```

- `Ir_Poll()` は loop から毎回呼ぶ。待たない。
- **押しっぱなしのリピート**（NEC のリピート信号 0xFFFFFFFF）は返さない。
- 同じコードが `IR_DEBOUNCE_MS`（500ms）以内に続いたら、押しっぱなし（または二重受信）とみなして返さない。
  続く間は、時間を延ばして捨て続ける（キーの押しっぱなし判定と同じ考え方）。
- NEC 以外の信号は返さない。数秒に1回だけ「NEC 以外の信号を受信」と1行出す（別のリモコンや雑音に気づくため）。
- 受け取ったボタンは、シリアルに1行出す：`[IR] 0xFFA857（▶）`。表にないコードは `（未登録）`。
  押しっぱなしのリピートは出さない。

## ボタンの割り当て：一時停止・再開（#0）

ケーブルなしで5分間の試験をするため、リモコンの **▶（0xFFA857）** で、`p` キーと同じ「一時停止／再開」を切り替える。

- **ボタンの選び方**：リモコンの中央付近にあって押しやすい。公式サンプル 05.3 でも、▶ は「止める」の意味。
  コードは `IR_BUTTON_PAUSE`（config.h）で変えられる。
- **切り替えの入口を1つにする**：`p` キーとリモコンの ▶ は、同じ `TogglePause()`（main.cpp）を通る。
  どちらから切り替えたかを、シリアルに出す（`一時停止（リモコン ▶）` など）。
- **押しっぱなし**：hal_ir が捨てる（リピート信号と、500ms以内の同じコード）。`p` キーも 250ms 以内の同じキーを捨てる。
- 走行中に押すと、`p` と同じくなめらかに減速して止まる（約1.3秒）。

### 目の合図（`behaviors/pause_cue.*`）

切り替わったことが、目で見て分かるようにする。目のレイヤーの振る舞い（優先度40）で、まばたき（10）・気づく（30）より優先する。

| 切り替え | 目 | 時間 |
|---|---|---|
| 一時停止 | 細める | 1.0秒（`PAUSE_CUE_PAUSE_MS`）。そのあと通常に戻る |
| 再開 | ゆっくり閉じて開く（細める → 閉じる → 細める） | 合計 0.5秒（150 + 200 + 150ms。`PAUSE_CUE_RESUME_*`）。そのあと通常に戻る |

- 「見開く」は ID9 の「気づく」と紛らわしいので使わない。ゆっくり閉じて開く動きは、普通のまばたき（約0.25秒）と区別できる。
- 合図の途中で、続けて切り替えられたら、新しい合図を頭から出す。
- LED（WS2812）とブザーは使わない（WS2812 は電池電圧と GPIO32 を共用していて共存が未確認。ブザーは方針5）。

## 調整パラメータ（config.h）

| 名前 | 初期値 | 意味 |
|---|---|---|
| IR_DEBOUNCE_MS | 500 | 同じコードがこの時間以内に続いたら捨てる |
| IR_BUTTON_PAUSE | 0xFFA857 | 一時停止・再開に割り当てるボタン（▶） |
| PRIORITY_PAUSE_CUE | 40 | 目：一時停止・再開の合図の優先度 |
| PAUSE_CUE_PAUSE_MS | 1000 | 一時停止の合図（目を細める）の時間 |
| PAUSE_CUE_RESUME_HALF_MS / PAUSE_CUE_RESUME_CLOSED_MS | 150 / 200 | 再開の合図（ゆっくり閉じて開く）の、細める時間（前後それぞれ）／閉じる時間 |

## 完了条件

- 動作：リモコンのボタンを押すと、シリアルにコードとボタン名が1行出る。押しっぱなしでも1行だけ。
  ビルドが通り、他の機能（超音波・首・モーター・目）が今までどおり動く。
- 確認：全ボタンのコードを押して確かめる（ここの表と違うボタンがあれば、表を直す）。
  → 2026-09-21 に実機で確認した：▶ は 0xFFA857、他のボタンも表と合っていた。押しっぱなしは1回だけ出た。
- 動作（一時停止・再開）：▶ を押すと一時停止と再開が切り替わり、目で合図が出る。押しっぱなしでも1回だけ切り替わる。
