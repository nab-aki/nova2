# ID 25：うろうろ（v1）

カタログ：分類C／難易度 中／依存 7, 9, 15／位置づけ 2／実装順 2

最優先方針「障害物を避けながら部屋をうろうろする」の中核。
止まって見回し、歩き、また止まる、を繰り返す。

## きっかけ

常に発動している（車体レイヤーの既定の振る舞い）。
ID9「気づく」・ID15「障害物で困る」が発動していない間、これが動く。

## 動作の流れ

```
[ため] → [正面を測る] → [左を測る] → [右を測る] → [決める]
   ↑                                                  ↓
   │                                    （横が近ければ）[片側旋回で向きを変える]
   │                                                  ↓
[減速] ← [巡航（ランダム 1〜3秒）] ← [加速] ← [正面へ戻して安定を待つ]
```

1. **ため**：止まってから `WANDER_REST_MS`（800ms）待つ。いきなり首を振らない（設計原則3）。
2. **見回し**：首の使用権を「測距」で取り、正面 → 左 → 右 の順に測る。
   - 角度は正面 ±`WANDER_SCAN_PAN_DEG`（50°）。servo1 は 34° / 84° / 134°。
   - 各方向で、首が安定（`Neck_IsSteady`）してから `WANDER_SCAN_SAMPLES`（3回）測る。
   - その方向の値＝3回のうち**最も近い値**（危険側に倒す）。
     3回とも「エコーなし」「範囲外」なら `ULTRASONIC_MAX_CM`（80cm）＝空いている扱い。
3. **決める**：
   - 左右のどちらかが `WANDER_SIDE_VERY_NEAR_CM`（25cm。仮の値）未満なら、**とても近い側と反対へ、
     後退してからその場回転**で避ける（下記「とても近いとき」）。反対側の遠さは問わない。
   - そうでなく、近いほうが `WANDER_SIDE_NEAR_CM`（40cm）未満で、かつ反対側のほうが遠ければ、
     **反対側へ片側旋回**して向きを変える（`WANDER_AVOID_PIVOT_MS`＝1200ms、左右とも約20°。浅い角度の壁への対策）。
   - 両方とも近い（通路のような場所）ときは向きを変えず、そのまま歩き出す。
   - 両方とも空いているときも向きを変えない。
4. **正面へ戻す**：首を正面・水平に戻し、使用権を返す。
   首が安定し、かつ測距の履歴が5回たまる（`Obstacle_IsReady`）まで待つ。
5. **歩く**：`MOTION_ACCEL_MS`（1600ms）で巡航速度まで上げ、
   `WANDER_RUN_MIN_MS`〜`WANDER_RUN_MAX_MS`（1000〜3000ms）のランダムな時間だけ巡航し、
   `MOTION_DECEL_MS`（1300ms）で止まる。加速・巡航・減速は ID9 と同じ。
6. 止まったら 1 に戻る。

途中で正面に障害物があると判定されたら、ID9（優先度30）が割り込んで即停止する。
このとき ID25 は `onStop` で目標速度を0にして待機し、ID9・ID15 が終わったら 1 から再開する。

### 片側旋回が止められたとき（中断をログに出す）

片側旋回は、安全層が障害物で止める動き（前進と同じ扱い）なので、途中で止められることがある。
歩き出す前は「あり」ではない（「あり」の間は ID9 が優先され、ID25 は動いていない）ので、
旋回を始められないことはない。止められるのは、旋回を始めたあとの次の2つ：

| 経路 | 条件 | ID25 の動き |
|---|---|---|
| ① 旋回中に「あり」に変わる | 旋回の開始で履歴を捨てたあと、5回たまってから直近5回のうち3回が 36cm 未満 | ID9（優先度30）が割り込み、ID25 は手放される（`onStop`）。**1行出す**。そのあとは ID9・ID15 が引き継ぐ |
| ② 非常停止（12cm 未満） | 1回の測距で発動。「あり」より前に止まる | 旋回が止まったことに気づいた時点で、**1行出して旋回を終え、`STATE_READY` へ進む**（旋回時間を待たない）。まだ「あり」なら ID9 が引き継ぐ |

- 障害物のときに「その場回転に切り替える」ことはしない。①では ID25 が手放されるので切り替える機会がなく、
  ②は非常停止距離未満で、回転を続けても意味がないため（2026-09-21 の検討。docs/decisions.md）。
- 持ち上げで止められたときは、この行を出さない（「持ち上げられました」の行と、やり直しがある）。

### とても近いとき：後退+その場回転（張りつき対策。2026-09-22 追加）

**きっかけ**：2026-09-22 の狭い部屋での5分間試験で、正面衝突は0回だったが、浅い角度の壁に片側旋回が
何度も止められ続けて**張りつく**問題が見つかった（試験時間173秒のうち14回、旋回が中断された）。
片側旋回は車体が前へふくらむ動きなので、壁までの余裕が少ないと安全層に止められやすい
（上の「片側旋回が止められたとき」の経路①）。旋回が中断されるたびに、ほぼ同じ位置・同じ向きから
歩き出しを繰り返すため、抜け出せなくなる。

**対策**：横のどちらかが `WANDER_SIDE_VERY_NEAR_CM`（25cm。仮の値）未満のときは、片側旋回ではなく
**後退してから、とても近い側と反対へその場回転**で離れる。後退・その場回転はどちらも
安全層が障害物で止めない動き（`docs/specs/common_obstacle.md`）なので、最後までやり切れる。

```
[FACE_FRONT] → [少し後退（RECOVER_BACK）] → [反対側へその場回転（RECOVER_TURN）] → [READY]
```

- **後退**：`TROUBLE_BACK_SPEED`・`TROUBLE_BACK_MS`（500ms）・`TROUBLE_BACK_RAMP_MS` を、
  ID15 とそのまま共通で使う（新しい調整値は増やさない）。trouble.cpp の `STATE_BACK` と同じ、
  後退→減速→静止を待つ、の2段階。
- **その場回転**：`TURN_ROTATE_LEFT`／`TURN_ROTATE_RIGHT` を1ステップだけ（`TurnTuning_StepMs`。約30°）。
  ID15 のような「空くまで回り続ける」再判定ループはしない。1回で `STATE_READY` へ進み、
  そこで障害物の有無を確かめてから歩き出す。
- **両方ともとても近い（コーナー）**ときは、より近い側（僅差でも）と反対へ回る。
- **ID9 に割り込まれない**：後退・その場回転の間は、優先度を `PRIORITY_WANDER_RECOVER`（35。
  `PRIORITY_NOTICE` の30より高く `PRIORITY_TROUBLE` の40より低い）にする。ID15 の立て直しと同じ考え方。
  - 理由：ID25 の既定の優先度（20）は ID9（30）より低いため、後退・その場回転の最中に
    `Obstacle_IsBlocked()` が真になると（回転で前方の見え方が変わるなど）、対策なしでは
    ID9 に割り込まれて向きが変わりきらないまま終わってしまう。ID15 は `active_` の間ずっと
    優先度40を返すため同じ問題が起きないが、ID25 は状態によらず一定の優先度だったので、
    この2状態の間だけ引き上げる。
  - **非常停止・持ち上げは影響を受けない**：非常停止（12cm未満）は、そもそも安全層が
    後退・その場回転を止める対象に含めていない（`MovingTowardObstacle()` が false を返す）。
    持ち上げは安全層が調停より後・優先度に関係なく毎ループ見ているので、いつでも効く。
  - 一時停止（`p`／リモコン）は、優先度を強制的に0にする既存の仕組みが働くので、後退・その場回転の
    途中でも止まる（なめらかに減速）。この場合だけ、途中で交代されたことになる。

**シリアル出力の例**：

```
[うろうろ] 左がとても近い（18.3cm < 25cm）ので、後退してから右へその場回転
[うろうろ] 正面へ戻す→後退
[動き] 目標速度 0.00→-0.04（300msかけて）
[うろうろ] 後退 500ms：その場回転 右へその場回転します
[動き] その場回転 右 キック PWM1600（1000ms）→ 保持 PWM1000 → 停止（合計 1300ms）
[うろうろ] その場回転→歩き出す準備
```

途中で交代された場合（通常は一時停止のときだけ）：

```
[うろうろ] 後退+その場回転の途中で交代しました（420ms で中断、一時停止のため）。向きは変わりきっていません
```

### 歩き出す前に止める条件

次のどれかに当てはまる間は、5（歩く）に進まない。

- 正面に障害物がある（`Obstacle_IsBlocked`）… ID9 が発動するので、実際にはそちらに移る
- 首が正面・水平でない、または安定していない
- 測距の履歴が5回たまっていない
- 持ち上げられている（`Safety_IsLifted`）

## ID25 と ID9 の役割分担（ID9 の変更）

いまの ID9 は「停止→加速→巡航→減速」の走行ループ自身を持っている。
ID25 も同じループを持つため、**走行ループは ID25 に移し、ID9 は「気づいた瞬間の反応」だけにする**。

| | 変更前（スプリント1） | 変更後（スプリント2） |
|---|---|---|
| 走る・止まるの繰り返し | ID9 | **ID25** |
| 障害物に気づいて即停止・目を見開く・停止後の距離を出す | ID9 | ID9（据え置き） |
| 気づいたあとの後退・方向転換 | なし | **ID15** |

ID9 の優先度は、気づいている間だけ返す形にする（それ以外は0）。
`src/behaviors/notice.*` から `STATE_REST`/`ACCEL`/`CRUISE`/`DECEL` を削り、
`STATE_IDLE`（何もしない）と `STATE_NOTICED`（気づいた）だけにする。

## 回転（その場回転・片側旋回）※共通部品（#0）

実測（docs/measurements.md）で、回転・旋回は前進より大きなPWMでないと動き出さないが、
いちど回り出せば下げても回り続ける。そこで**キック（動き出し）→ 保持**の2段階で出す。

| 種類 | 左右の出力 | キック | 保持 | 使う場面 |
|---|---|---|---|---|
| その場回転 左 | 左輪 後退・右輪 前進 | 1600（1000ms） | 1000 | 壁の前での方向転換（ID15）。1ステップ 1300ms で約30° |
| その場回転 右 | 左輪 前進・右輪 後退 | 1600（1000ms） | 1000 | 同上 |
| 片側旋回 左 | 左輪 停止・右輪 前進 | 1400（300ms） | 1450 | 広い場所での向き変え（ID25）。1ステップ 1200ms で約20° |
| 片側旋回 右 | 左輪 前進・右輪 停止 | 1400（300ms） | 1450 | 同上 |

上の値は **一旦の決定値（2026-09-21。床で調整キーを使って探した）**。5分間の試験で動きの印象を見て見直す。
片側旋回は保持（1450）がキック（1400）より大きく、キックの意味が薄い（実質 1450 一定）ので、見直し候補。

- キックを出す時間は `MOTOR_ROTATE_KICK_MS`（1000ms）・`MOTOR_PIVOT_KICK_MS`（300ms）。
  最初は仮値の300msだったが、実機で回り始めるまでの時間が300msより長いと分かり、下の「回転の調整キー」で探した。
- 使い分けは catalog.md の ID25 のメモのとおり
  （壁の前ではその場回転＝角が壁に当たらない、広い場所では片側旋回＝柔らかく見える）。
- 値は正規化速度ではなく生のPWM。HAL に `Motor_DrivePwm(int leftPwm, int rightPwm)` を足し、
  `Motion_StartTurn` / `Motion_StopTurn` / `Motion_IsTurning` を motion.* に足す。
  モーターに書き込む場所を1つ（motion.*）に保つため、別モジュールにはしない。
- 回転を始めるとき・終えるときに `Obstacle_Reset()` を呼ぶ。
  車体が回っている間の測距は別の方向を見ているため、履歴に混ぜない。
- 回転中に `Motion_SetSpeed` を呼ぶと回転は取り消される（直進が優先）。

**左右の向きは実機で確認する。** 左＝M1・M2、右＝M3・M4 という測定ツールと同じ定義を前提に
しているが、実際にどちらへ回るかは目で見て確かめ、逆なら定義を入れ替える。

## 共通部品への変更（#0）

[common_obstacle.md](common_obstacle.md) の安全層の節にも反映してある。

### 1. 持ち上げたら即停止

- ライントラッキングが `111`（`SAFETY_LIFT_TRACK` = 0b111）になったら、その場でモーターを止める
  （床では `000`、持ち上げると `111` と実測）。回転中なら回転も取り消す。
- 復帰は慎重にする：`111` 以外が `SAFETY_LIFT_CLEAR_COUNT`（3回＝約300ms）続いたら解除。
  止めるのは1回で即座に、戻すのは3回続けて、とするのは、宙に浮いたまま車輪が回るのを避けるため。
  ライントラッキングは `TRACK_READ_INTERVAL_MS`（100ms）ごとに読むので、数えるのは
  「読んだ回数」で数える（毎ループ数えると数msで解除されてしまう）。
- **持ち上げを検知したら、動きの状態を確実に0に戻す。**
  `Motion_EmergencyStop()` で、なめらか加減速の目標速度・現在速度をどちらも0にし、
  回転中なら回転も取り消し、モーターに0を書き込む。
- **床に戻ったら、続きからではなく、やり直す。**
  持ち上げられている間、ID25・ID15 は状態を進めない。下ろされたら
  ID25 は「ため」から（見回しをやり直す）、ID15 は最初（後退）からやり直す。
  持ち上げられている間に向きも場所も変わっているので、持ち上げ前の測距値や
  「あと何回回れば一周か」を引き継がない。

### 2. 障害物での即停止は「前進」と「片側旋回」だけを止める

いまの安全層は、障害物があれば動きをすべて止める。これだと ID15 が壁の前で
立て直せない（後退も回転もできない）ため、次のように分ける。

| 動き | 障害物があるとき | 理由 |
|---|---|---|
| 前進 | **止める** | 障害物に近づく |
| 片側旋回 | **止める** | 片輪が前に出るので、車体が前へふくらむ |
| 後退 | 止めない | 障害物から離れる |
| その場回転 | 止めない | 中心が動かないので、角が壁に当たらない |

持ち上げの停止は、これと関係なくすべての動きを止める。

### 3. 回転角を測るためのデバッグキー（本体のシリアル）

回転1ステップで何度回るかを実測して（その場回転 約30°、片側旋回 約20°。docs/measurements.md）、`WANDER_AVOID_PIVOT_MS` と `TROUBLE_MAX_STEPS` を
決めるのに要る。本体のシリアル（115200bps）から1文字で、1ステップだけ回せるようにする。

| キー | 動き | 時間 |
|---|---|---|
| `3` | その場回転 左 | その場回転の1ステップの時間（初期 `TROUBLE_TURN_STEP_MS` 1300ms） |
| `4` | その場回転 右 | 同上 |
| `5` | 片側旋回 左 | 片側旋回の1ステップの時間（初期 `WANDER_AVOID_PIVOT_MS` 1200ms） |
| `6` | 片側旋回 右 | 同上 |
| `?` | キーの一覧を表示 | ― |

キーの割り当ては tools/measure_m2 のモードと同じにする（同じ操作で測れるようにするため）。
時間は実際に振る舞いが使う設定値そのままで、デバッグ用の別の値は持たない。

**受け付ける条件**（ひとつでも欠けたら、理由を1行出して無視する）：

- 前のステップが終わっている（実行中でも予約済みでもない）
- 車体が止まっている（目標速度・現在速度がどちらも0で、回転していない）
- ID15「障害物で困る」が動いていない
- 持ち上げられていない

車体レイヤーの振る舞い（優先度 `PRIORITY_DEBUG_TURN` = 50）として作り、
ID25・ID9・ID15 のどれよりも優先する。1ステップ終わったら優先度を0に落として、
ふだんの振る舞いに戻す。

1ステップが終わったとき、**その間の電池電圧**も出す（動き出す前の値／ステップ中の最低値と、
最低になった時刻・読み取り回数）。ADC を毎ループ読むので、状態行（500ms間隔）では逃す短い電圧降下も拾える。
実測では、回転中に 7.7V 前後から 6.40V まで落ちて見えた。大電流による実際の電圧降下か、ADC の乱れかは
まだ切り分けていない（下の調整で PWM を変えたときの最低値の変わり方で見る）。

**障害物の近くでも回せる**：デバッグ回転の1ステップの間だけ、安全層の「障害物あり」による停止を外す。
外さないと、前方に障害物がある場所では片側旋回（5・6）が数msで止められて、まったく回らない
（その場回転 3・4 は止めない規則なので影響しない）。持ち上げの停止と、非常停止距離（12cm）未満での
停止は外さない。ステップの開始で外し、終了・中断・取り消しのすべてで戻す。

**押しっぱなしのリピートは捨てる**：同じキーが `DEBUG_KEY_REPEAT_MS`（250ms）以内に続いたら、
自動リピートとみなして無視する（黙って捨てる）。1ステップが終わった直後にリピートが届くと、
調停がまだ手放していない間に予約が入り、優先度だけが残って以後のキーが効かなくなったため
（2026-09-21 に実機で発生。`p` の切り替えにも同じガードを効かせる）。
それでも予約が入った場合に備え、`onUpdate` で予約を見つけたらそこで次のステップを始める。

### 4. うろうろの一時停止（`p` キー）

回転角を落ち着いて測るため、ID25 と ID15 を止められるようにする（`src/core/debug_pause.*`）。

| キー | 動き |
|---|---|
| `p` | 一時停止 ⇔ 再開を切り替える |

- **一時停止中**：ID25 と ID15 の優先度が0になり、車体はその場で止まったままになる
  （動いていたら、なめらかに減速して止まる。首は向いていた向きのまま）。
  まばたき（目レイヤー）は続く。ID9 の気づく反応は、障害物があれば動く（止まっているだけなので害はない）。
- **一時停止中も 3〜6 を受け付ける**（受け付ける条件は変わらない。止まっているときだけ）。
- **再開**：ID25 は「ため」から始める。ID15 は、塞がっていれば最初（後退）からやり直す。
- **起動直後**：`DEBUG_START_PAUSED`（config.h。既定 0）を 1 にすると、一時停止の状態から始める。
  0 なら今までどおり、起動したらすぐうろうろを始める。
- 状態行に「一時停止中」を出す。`?` のキー一覧にも現在の状態を出す。

### 5. 回転の調整キー（一時停止中だけ）

実機で、その場回転は 180° 回すのに 30 ステップ（約 6°/ステップ）かかり、片側旋回はほとんど回らなかった。
回り始めるまでの時間がキック300msより長いと考えられるので、床の上で値を探せるようにする
（`src/core/turn_tuning.*`）。

**探した結果（2026-09-21。一旦の決定値）**：その場回転は 1ステップ1300ms・キック1000ms（PWM1600）・保持PWM1000 で
左右とも約30°。片側旋回は 1ステップ1200ms・キック300ms（PWM1400）・保持PWM1450 で左右とも約20°。
値は config.h に反映済み（docs/measurements.md に記録）。

その場回転と片側旋回それぞれ（左右は共通）について、次の4項目を、キーで増減する。

| キー | 項目 | 刻み | 範囲 |
|---|---|---|---|
| `q` / `a` | 1ステップの時間 +／− | 100ms | 100〜3000ms |
| `w` / `s` | キックの時間 +／− | 50ms | 0〜2000ms（0 でキックなし＝保持のPWMから始める） |
| `e` / `d` | キックのPWM +／− | 50 | 500〜2000 |
| `r` / `f` | 保持のPWM +／− | 50 | 500〜2000 |
| `g` | 調整の対象を切り替え（その場回転 ⇔ 片側旋回） | ― | ― |
| `v` | 両方の現在の値を表示 | ― | ― |

- **対象の選び方**：最後に押した回転キー（3・4 ならその場回転、5・6 なら片側旋回）が対象になる。`g` でも切り替えられる。
  押すたびに、どちらの対象かを1行目に出す。
- **一時停止中だけ効く**。一時停止でないとき、回転の最中は理由を1行出して無視する。
- **変えるたびに表示する**：現在の値を1行と、config.h にそのまま貼れる `#define` を4行
  （行頭の時刻・タグなし。`TROUBLE_TURN_STEP_MS`／`WANDER_AVOID_PIVOT_MS`、`MOTOR_*_KICK_MS`、`MOTOR_*_KICK_PWM`、`MOTOR_*_HOLD_PWM`）。
- **書き込み直すと元に戻る**。実行時の値だけを変え、config.h は変えない（貼って直すのは人の指示で行う）。
- **実際の動きにも効く**：motion（キック・保持）、ID15（1回の回転の時間）、ID25（向き変えの時間）、
  デバッグキー 3〜6 は、すべて同じ調整値を読む。調整したあと `p` で再開すれば、そのまま一連の動きで確かめられる。
- 調整キーは連続で押したいので、押しっぱなしのリピート判定を短く（`DEBUG_TUNE_REPEAT_MS` 60ms）してある。

## 優先度

| レイヤー | 振る舞い | 優先度 | 発動する条件 |
|---|---|---|---|
| 車体 | デバッグ回転（`3`〜`6`） | 50 | キーを受け付けたときだけ。1ステップで終わる |
| 車体 | 障害物で困る（ID15） | 40 | 気づいて止まったあと、正面が塞がっている間 |
| 車体 | **うろうろ：後退+その場回転**（2026-09-22 追加） | **35** | 横がとても近く、後退+その場回転をしている間だけ（張りつき対策。下記） |
| 車体 | 気づく（ID9） | 30 | 障害物がある、または気づいた直後の反応中 |
| 車体 | **うろうろ（ID25、既定）** | **20** | 常に（既定の振る舞い） |

## 初期値の根拠

- **見回しの角度 50°**：servo1 の可動範囲は 20〜140°、正面 84° なので、
  左右対称に取れるのは ±56° まで。実測の安定時間は ±55° で最長160ms、
  式（60＋角度×2）では 50° → 160ms で収まる。
  浅い角度の壁ほど大きく振ったほうが正面から見られる（入射角が浅いと測れない）ので、
  対称に取れる範囲でなるべく大きくした。
- **横が近い＝40cm**：停止閾値 36cm より少し広い。
  横を通り過ぎるだけなら 36cm でも当たらないが、浅い角度の壁は
  進むほど寄ってくるので、気持ち広めに見る。
- **巡航 1〜3秒**：ID9 の 1500ms を中心に、前後に振った。
  加速1.6秒＋減速1.3秒が付くので、1回の移動は 3.9〜5.9秒。
  実測の巡航速度 41.1cm/s から、進む距離はおよそ 60〜140cm。
- **片側旋回 1200ms**：当初は 500ms と短くしたが、ほとんど回らなかったので、調整キーで探した（一旦の決定値）。
  1ステップで約20°（measurements.md）。5分間の試験で動きの印象を見て見直す。
- **横がとても近い＝25cm（仮の値）**：正面の停止閾値 `OBSTACLE_STOP_CM`（36cm）より内側に置いた。
  片側旋回は車体が前へふくらむ動きなので、壁までの余裕が少ないほど安全層に止められやすい。
  `WANDER_SIDE_NEAR_CM`（40cm）との間に余裕を持たせ、非常停止距離（12cm）よりは十分上にしてある。
  確度の高い実測はまだない。実機で見回しのログ（横の距離）を見ながら詰める。

### 観察項目（合否には含めない）

- **壁と平行に進むとき、横の壁を見落とすか。**
  横の判定 `WANDER_SIDE_NEAR_CM`（40cm）は、首を50°振って斜めに測った距離なので、
  壁が進行方向と平行なら、横方向の実距離は 40 × sin50° ≒ **31cm** に当たる。
  つまり横に 31〜40cm の壁は「近い」と判定されない。
  壁に沿って歩かせて、どのくらい寄ると避けるようになるかを見る。
  見落とすようなら `WANDER_SIDE_NEAR_CM` を上げるか、見回しの角度を変える。
- 片側旋回・その場回転が1ステップで何度回るか（デバッグキー `3`〜`6` で測る）。
- **後退+その場回転が選ばれた場面での、実際の余裕**（`WANDER_SIDE_VERY_NEAR_CM` 25cm の妥当性。2026-09-22 追加）。
  選ばれたときの見回しログの距離と、後退・回転がぶつからずやり切れたかを見る。
