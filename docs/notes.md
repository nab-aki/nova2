# 常設の注意書き

何度も参照する手順・コツ・既知の限界をまとめる。毎回は読まず、作業に必要なときに読む。
現在地・次にやること・未解決の点は docs/handoff.md。毎回守るルールは CLAUDE.md。

## 1. ビルドと書き込み

- **書き込みは、ユーザーが指示したときだけ。書き込み前にユーザーがシリアルモニタを閉じる**（COM4 が使用中だと失敗する）。
- 本体の書き込み：`~/.platformio/penv/Scripts/pio.exe run -t upload --upload-port COM4`（fnk0053）。
  ツールは `-d tools/<名前>` を付ける。ツールを書き込むと本体のファームは上書きされるので、あとで本体を書き戻す。
- `pio.exe device list` でポートが見えないときは、USBケーブル・本体の電源を確認する。
- ビルドだけは `pio run`。ホストに g++ はない。
- サーボのチャンネルを入れ替えたビルド（環境 `fnk0053_swap`。首の切り分け用）は 2026-10-12 に消した。コミット efc737f に残っている。
- **書き込みで、調整キーで変えた値は元に戻る。** 値を決めたら config.h に反映する（ユーザーの指示で）。
- IR のライブラリは `lib_deps`（初回ビルドはネットワークが必要）。

## 2. シリアルとデバッグ機能（本体。115200bps。`?` で一覧）

- `p` 一時停止／再開、`3`〜`6` 回転を1ステップ、`q a w s e d r f` 回転の調整（一時停止中だけ。`g` 対象切替、`v` 表示）。
- ジャイロ：`j` いまの値と設定、`z` ゼロ点補正のやり直し、`m` 静止測定60秒（一時停止中・床に置く）、
  `n` モーターの振動の測定 約31秒（一時停止中・**車輪を浮かせ、前を30cm以上あける**。どのキーでも中断）。
  回転すると、止まったあとに `[ジャイロ]` の行で回った角度が出る（正＝上から見て反時計回り）。
  `m`・`n` の結果のうち `|` で始まる行は、measurements.md にそのまま貼れる表の行。
  詳細は docs/specs/common_gyro_checklist.md「第1段階『まず測るだけ』の実装」。
- 見回しの試験：`o`（一時停止中・床に置く・ケーブルをつないだままでよい）。車体は動かさず、うろうろ（ID25）と同じ見回し
  （ため → 正面 → 左 → 右 → 正面へ戻す → 測距の履歴がたまるのを待つ）を20回くり返す。どのキーでも（リモコンの ▶ でも）中断し、そこまでのまとめを出す。
  1回ごとに「3方向の距離と有効数・首の角度・かかった時間」、打ち切られたら「どこの途中で、何が割り込んだか」が出る。
  最後のまとめのうち `|` で始まる行は、measurements.md に貼れる表。
  障害物の判定・安全層・気づく（ID9）・首の調停は、うろうろ中と同じに働く（うろうろと同じ優先度で調停を通している）。
  試験中に正面が塞がると ID9 が割り込み、空くまで戻らない（一時停止中は ID15 が動かないため）。前を空けるか、キーで中断する。
  見るもの：首が毎回左右に動くか（目で見る。ログの「首 84°/134°/34°」は指示した角度）／同じ場所で値がばらつかないか／打ち切りが出るか。
  1回ごとに「読み戻し」の行も出る（各方向を測り終えた時点で、サーボのチャンネルを PCA9685 から読んだ値。書いた値と同じなら「一致（パルス幅）」。
  正面 293・左 407・右 179）。まとめに不一致の回数が出る。不一致がある → 指示が IC に届いていない。
  全部一致なのに首が動かない回がある → IC より先（サーボの電源・サーボ・配線）。
  各回の行の最後に「指示の直後150msのジャイロ 左／右」も出る（左右へ向ける指示の直後 150ms の、車体の回る速さの最大の絶対値。
  首が振れると車体が反動で揺れるので、首が実際に動いたかの目安。ジャイロが読めていなければ「-」）。
  `o`・`u` の各回の行には「動き出すまで」も出る（首へ指示を出すたびに〔1つ目・2つ目・正面へ戻す〕、指示からジャイロの絶対値が初めて
  `DEBUG_SCAN_ONSET_DPS`〔【仮】2.0dps〕以上になるまでの ms。超えなければ「-」。記録だけで、動きの判断には使わない）。
  「正面へ戻す」は最大1000ms 見るので、各回の行は少し遅れて（約0.5秒後に）出る。まとめに指示ごとの最小・最大・「-」の回数が出る。
- 見回しの試験（順番が逆）のキー `i` は 2026-10-12 に消した。コミット efc737f に残っている。
- 実験用のキー `k`（上下のサーボへの書き込みを省く／省かない）は 2026-10-12 に消した。コミット efc737f に残っている。
- 見回しの試験（上下も動かす版）：`u`（一時停止中・床に置く）。`o` と同じ順（正面 → 左 → 右）で、1つ目の指示（左）と同時に上下も動かす
  （servo2 98°→113°。2つ目はそのまま、正面へ戻すとき 98° へ戻す）。
  上下が上がるので、1つ目・2つ目の距離は水平のときと違う値になる。最初の1回は、首の配線が突っ張らないか目で見る。
  各回の行とまとめに、上下の動きの「動き出すまでの時間」と「指示の直後150msの最大」（ジャイロの水平2軸の合成。しきい値【仮】1.0dps）が、左右とは別に出る。
- 見回しの試験（`o`・`u`）の1回ぶんは、行が切れないように分けて出る：1行目＝距離・首・かかった時間／2行目＝ジャイロ（左右）／
  3行目＝ジャイロ（上下。`u` だけ）／最後＝読み戻し。
  ログの1行は 384 バイトまで（hal_log）。日本語は1文字3バイトなので、長い行を足すときは分ける。
- 試験の集計：`t` 表示・`h` 保存・`x` 消去。起動時のリセット理由と、足あと（ブラウンアウト時に自動表示）も出る。
  `t` の最後に、I2C の失敗（機器ごとの「失敗/回数（タイムアウト）」）と、ライントラッキングが読めずに止めた回数が出る。
  どちらも起動からの累計で、保存されない（電源を切る・書き込む・リセットで 0 に戻る。`x` では消えない）。
- IR：リモコンの ▶（0xFFA857）で一時停止／再開。切り替えたら目で合図。
- **`DEBUG_START_PAUSED` は 1**（config.h）。起動直後は一時停止で、▶ か `p` で開始する。
  ケーブルなしの試験ではこのまま便利。すぐ動かしたいときは 0 にする。
  試験の集計は、起動時に一時停止のままだと「再開」まで始まらない（1で始まる設定と整合させてある）。
- シリアルを読むだけなら、DTR/RTS を下げて開けば本体はリセットされない（pyserial で `dtr=False, rts=False`）。
- **持ち上げ中（ライン111）は、`3`〜`6` も受け付けない**（安全層が止める）。床に置いて 111 が消えてから使う。
- 回転キー `3`〜`6` の1ステップの間だけ、障害物「あり」による停止を外している（デバッグ用。非常停止12cm未満と持ち上げは残す）。
  本番の ID25・ID15 は外さない。
- **ToF の単体試験 `l8cx_ranging`**（experiments/vl53l8cx_build。本体ではない。キーの説明は main.cpp の先頭）：
  `g` 表（生）／`G` 表（Nova の向き）／`p<数字>` 上下だけを水平からの角度で止める（`p` だけ＝水平。範囲 -8〜+42°。止まるまで待ってから `G`）／`r` 4×4・8×8／`s` 集計／`b` 電池／`c` Wire1 400⇔100kHz／`n` 首振り（u と同じ）／`a<数字>` 左右だけ（上下は水平から。例 `a0`・`a40`）／
  `v<数字>` 上下だけ（数字なし＝+15°）／`h` PWM を止めて手で動かす（Enter で終わり）／`x` 中断。`a`・`v` は数字のあと Enter。
  上下は上が +、範囲は -8〜+42°（servo2 90〜140°）。外なら実行しない（`a45` は不可）。`n`・`a`・`v` は電池 6.0V 未満なら動かない。
  **首の「水平」（servo2 98°）が本当に水平かの確かめ方**：`p` で水平にして、センサーの面に定規を当て、床（机の面）との角度を横から見る（垂直なら水平）。床の距離が高さ 12.5cm からの計算より近かったので、わずかに下を向いている疑いがある（未確認）。
  Wire のエラーの行は出さずに種類ごとに数え、集計に「段階・推定の角度の分布・失敗の記録（最初の20件）・やり直しの回数」が出る。
  `h` のときだけ、止まったら stop・get_resolution を飛ばしてすぐ init からやり直す（短くする）。
  [rec] の1行目に「最初の失敗」（順調な状態から最初のエラーの時刻・角度・段階）と「測れていた時間」、2行目にやり直しの内訳（各 ms・終了時刻）が出る。集計にも測れていた時間の min/avg/max。
  **モニタリング（スプリント3.6-2）**：`src/l8cx_ranging/wifi_secrets.example.h` を `wifi_secrets.h` にコピーして値を書く（.gitignore 済み。なければ Wi-Fi なしで動く）。起動の 20 秒後（`MONITOR_BASELINE_MS`）に Wi-Fi を始め、シリアルに `[mon] IP=...` が出る。その IP をブラウザで開く（`w` でもう一度出せる）。IP を固定するときは `wifi_secrets.h` の4行を有効にする（DHCP の範囲の外の番号）。調整値は monitor.cpp の先頭。

## 3. 試験の集計・足あとの読み方と保存

- ID25 の向き変え（その場回転）が途中で交代されたときは、`[うろうろ] 向き変え（その場回転）の途中で交代しました` の行が出る。
  試験の集計では「旋回 中断」として数える（関数名は片側旋回だった頃の `TestStats_RecordPivot*` のまま）。
  後退+その場回転（張りつき対策）が途中で交代されたときは別の行・別カウント（`後退回転 実施/中断`）で、
  優先度35のため通常は一時停止のときだけ出る。
- 試験の集計・足あとはNVS（フラッシュ）に書く（キーは `STORAGE_KEY_TEST_STATS`・`STORAGE_KEY_TRACE`、
  名前空間は共通の "nova"）。`TestRecord`・`TraceSaved` の構造を変えると、保存済みのデータは読み捨てられる（`magic` で判定）。
- **足あと**（`hal/hal_trace.*`）は `RTC_NOINIT_ATTR`（RTCスローメモリ）を使う。電源が入ったままの
  再起動では消えないが、電池を外すなど電源を完全に切ると内容は不定になる（`magic` で判定）。
  `t` で見られるのは車体レイヤーの振る舞い・状態の交代だけ。

## 4. 既知の限界・ハードウェアの注意

- ID15 の既知の限界：後方にセンサーがない／狭い場所では一周しても空かないことがある／浅い角度の壁は見つからないことがある。
- 首：正面でしばらく止まったあとの最初の首振りが、約10回に1回（240回中24回）、約0.5秒遅れる。最初に見る向きの値が正面の値になる。
  原因は左右のサーボ自体（ケーブルを含む）にほぼ絞れていて、ソフトでは直せない。対策は入れない（docs/specs/common_neck.md「結論と方針」）。
- 30°より浅い壁は検知できない（ID26 で対処）。45°の壁は近距離で遠く出る（実測）。
- 電池 7.0V は仮の動作下限（余裕の計算に使った。ID22 で見直す）。走行中の電池電圧の読み取りは乱れる（判定には使わない）。
- IR：GPIO0 は起動時のモード選択（strapping）のピン。起動の瞬間にリモコンを押さない。
- WS2812 は電池電圧と GPIO32 を共用しているので、起動時に全消灯を1回送るだけで、以後は使わない。
- 片側旋回のコード（`TURN_PIVOT_*`・キー5・6・調整値）は残してある。広い場所での方向転換として将来使い直す
  （catalog.md ID21・ID4、案A＝止める側をブレーキ）。
- 旧タイヤ時代（2026-09-21〜09-26）の旋回の測定値は無効。measurements.md に【旧タイヤ状態・現在は無効】を付けてある。

## 5. 教訓

- **電流が大きい動きで電圧関連の不具合が疑われたら、ソフトの「ため」だけでなく配線の径（電流容量）も早めに疑う**
  （2026-09-22〜23 のブラウンアウト。原因は AWG26 相当の細い配線。経緯は measurements.md・decisions.md）。
