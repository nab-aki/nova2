セッションを終了します。次の手順を行ってください。
（このファイルは独自コマンドの定義です。更新する対象は `docs/handoff.md` で、別のファイルです。）

追加の情報（あれば反映する）：$ARGUMENTS

1. `docs/handoff.md` の「最終更新」「現在地」「次にやること」「未解決の点」を、このセッションの内容で更新する。
   - 日付は、実施日（試験・測定・作業をした日）と判断日（決めた日）を取り違えない。相対的な言い方は日付に直す。
   - いま Nova に入っているファーム（本体か、tools/ のツールか）が本体でないときは、必ず「現在地」に書く。
2. 上の「追加の情報」があれば、反映する。
3. 未記録の内容があれば、正本にあわせて反映する。
   - 実測値 → `docs/measurements.md`
   - 仕様や方針を変えた理由 → `docs/decisions.md`（1行）
   - 状態の変化 → `docs/catalog.md`
   - 実機評価・仕様の詳細 → `docs/specs/` の該当ファイル
   - 常設の注意書き（何度も参照する手順・コツ・既知の限界） → `docs/notes.md`
4. 下の「肥大化させない決まり」を守る。
5. 変更点を日本語で短く要約し、`#0` でコミットする。プッシュと書き込み（upload）はしない。

## 肥大化させない決まり

- `docs/handoff.md` に書くのは「現在地」「次にやること」「未解決の点」だけ。目安は100行以内。
- 完了した試験結果・経緯・解決済みの問題は、正本（各 spec の「実機評価」、`docs/measurements.md`、
  `docs/decisions.md`）に記録があることを確かめてから外す。記録がなければ、移してから外す。
- 無効になった値や古い記述は残さない。
- 100行を超えそうなときは、何をどこへ移すかを私に示し、確認を待ってから整理する。
